# 원본 Excel 대비 기능·데이터 검증

기준일: 2026-09-16. 개인 금융금액과 원문 내역은 이 문서나 테스트 fixture에 기록하지 않는다.

## 1. 초기 PoC에 대한 판단

`64c2483` 시점의 PoC는 원장·사용자 정의 태그·자산 이동·공동 편집의 핵심 흐름을 보여주는 단계였다. **원본 Excel의 모든 내용을 실사용 가능한 설정과 화면으로 담았다고 볼 수 없었다.**

| 영역 | 당시 부족했던 부분 | 보완하는 실제 사용 흐름 |
| --- | --- | --- |
| 카드·통장 | 예시 항목 조회 위주, 사용자 관리 불가 | 생성·상세 수정·보관·복원, 계좌·자산 연결, 예상 대금 |
| 자산·대출 | 현재 잔액과 이동 위주 | 기준일, 관측/최초 잔액 구분, 과거 잔액, 연간 추이, 대출 수동 조건 |
| 가계부 | 목적별 생성·연결·총예산 중심 | 설정 수정, 회계 시작일, 고정지출 기준, 원본 분류 대응, 조회 범위 |
| 분류 | 자유 유형·옵션은 가능, 원본 종속 분류 미보존 | 대분류→소분류 관계와 선택 검증, 다른 부모 아래 동명 옵션 |
| 계획 | 대부분 미구현 | 월·주·항목 예산, 목표, 급여 배분, 행사, 결제 일정 |
| 통계 | 제한적인 태그 합계 | 기간·조건 조합, 연간 분류×월, 무지출 달력, 결제수단·하위 가계부별 분석 |
| 데이터 | 원본 가져오기·전체 백업 불가 | XLSX/CSV 미리보기·매핑·원본 검토함·중복 방지·JSON 왕복 |
| 저장·계정 | 로컬 예시 계정, 수동 저장 | 수정 자동 저장·기기 초안, 실제 OIDC 구현, 작성자·변경 전후 이력 |

최신 통과 결과와 운영 미검증 범위는 [구현 현황](./implementation-status.md)을 따른다.

## 2. 원본 범위와 유지 방식

원본은 28개 시트(표시 25개, 숨김 3개)다. 월별 고정/일반 입력, 연간 집계, 급여 배분, 자산·대출·예비금, 카드·통장·결제일, 설정, 가족 행사와 메모를 검사했다.

- 의료비 전용 정산 시트는 사용자 결정에 따라 제외한다. 일반 의료 지출에 사용된 사용자 분류는 유지한다.
- 서식·장식·숨김 계산 보조표를 웹 화면으로 복제하지 않는다. 계산 목적과 사용자가 입력한 사실을 보존한다.
- 원본 수식·외부 링크·매크로·문서 내 지시문을 실행하지 않는다. 저장된 계산값은 사용하되 검증할 수 없는 값은 검토 대상으로 남긴다.
- 예비금은 자산 분류다. 여행 가계부나 예산과 자동 연결하지 않는다.
- 저축은 자산 이동으로 연결한다. 카드 납부 예정은 별도 정보이며 소비 지출을 다시 만들지 않는다.

## 3. 실제 자료 대조

원본 파일은 수정하지 않았다. 브라우저용 OOXML 해석 결과를 독립된 Python/openpyxl 계산과 비교하고, 별도 임시 Worker/D1에서 가져오기·재가져오기·백업 왕복을 확인한다. 운영 DB나 기존 로컬 PoC에는 실자료를 반영하지 않는다.

| 검사 | 결과 |
| --- | --- |
| 월별 금액 입력 행 | 695행 |
| 유효한 수입·지출 | 633행. 월별·연간 건수와 금액이 독립 계산과 모두 일치 |
| 날짜·분류 등 불완전 행 | 46행. 임의 날짜나 분류를 만들어 넣지 않음 |
| 유효한 저축 원본 | 16행. 출금·입금 자산을 지정해야 실제 자산 이동으로 반영 |
| 저축 원본 전체 | 24행. 위 불완전 행에 포함된 저축 8행과 유효 16행의 합계 |
| 카드 관리 / 통장 관리 | 카드 7개. 통장 표는 번호가 있는 빈 템플릿이므로 입력 계좌 0개 |
| 자산 후보 / 월말 관측 | 관리 정보 24개, 월말 관측 68개. 같은 실제 자산인지 불명확한 항목을 이름만으로 합치지 않음 |
| 예비금 원본 | 유입 16행, 사용 24행. 월별 원장과 중복 여부·유입의 경제적 성격 확인 필요 |
| 계획 | 21개 추출. 공란 월 예산을 임의의 0원 예산으로 생성하지 않음 |
| 원본 메모 | 관리 표 하단·급여 배분 보조표·불완전 행사 자료를 출처와 함께 보존 |

위 대조에서 결제수단의 의미와 금융기관 대사는 별도다. 금액 검증용 임시 DB에서는 원본 결제수단 이름을 지정한 검증 항목에 명시적으로 연결했다. 실제 가져오기 UI에서는 각 원본 이름에 기존 항목 또는 새 항목의 종류를 직접 선택한다.

## 4. 자동으로 확정할 수 없는 원본 내용

| 원본 상태 | 처리 |
| --- | --- |
| 금액만 있고 날짜가 없거나 유효 범위를 벗어남 | 미리보기에서 보완하거나 원문·좌표를 검토함에 보존 |
| 저축의 실제 출금·입금 자산이 없음 | 자산 이동을 추정하지 않고 연결을 요청. 수입·지출 합계에서 제외 |
| 자산 표의 월말 잔액만 있음 | 첫 관측일을 기준으로 가져오며 관측 전 잔액은 미확인. 이후 월말은 조정 차액으로 보존하며 저축 실적 0 |
| 대출 원금과 실제 현재 잔액의 관계 불명 | 대출 조건은 보존하고 잔액·기준일은 확인 필요 |
| 예비금의 유입·사용과 월별 원장 중복 불명 | 이관 화면에서 확실한 별도 지출만 연결하거나, 원장 화면에서 기존 거래의 자산 배분을 직접 수정. 검토함은 원문·상태·메모를 제공하며 자동 전환하지 않음 |
| 가족 행사 달력과 예산표의 행이 다름 | 같은 행이라는 이유로 연결하지 않음. 날짜가 없는 예산·결산은 검토 자료로 보존 |
| 자산 날짜 머리글의 `+31` 계산으로 월이 어긋남 | 설정 연도·시작월에서 실제 달력 월말을 도출하고 변경 근거를 보존 |
| 예비금 분류별 잔액이 음수를 0으로 숨김 | 숨겨진 음수를 실제 잔액이라고 받아들이지 않고 원문·불일치를 보존 |

**검토함에 보관했다는 것은 금액 반영까지 끝났다는 뜻이 아니다.** 미확정 자료의 사실을 잃지 않고 사람이 연결을 결정할 수 있다는 의미다. 검토 완료 상태만 바꿔도 돈이나 거래가 생성되지는 않는다.

## 5. 회귀 검증 기준

1. 같은 출처·원본 위치를 다시 가져와도 거래·자산 효과가 증가하지 않는다.
2. 이미 가져온 원본 내용이 바뀌면 기존 기록을 조용히 덮어쓰지 않는다.
3. 불완전 행 보완 후 원문은 그대로 보존되고 유효한 거래만 한 번 생성된다.
4. 미리보기 도중 다른 사람이 수정하면 최신 자료로 다시 대조해야 한다.
5. 월말 관측 잔액, 계획, 태그 관계, 저축 집계값은 JSON 백업·복원 후 동일하다.
6. 원본 개인정보·금융자료를 Git에 넣지 않으며 기본 테스트는 합성 자료만 사용한다.
7. 관측에 이미 포함되었을 수 있는 과거 저축·예비금 사용은 다시 자산에 반영하지 않고 검토 대상으로 남긴다.
8. 재가져오기에서 기존 검토 메모를 보존하고, 원본 식별자가 같은 자료의 가계부를 조용히 변경하지 않는다.

실자료 검증은 파일 경로를 환경변수로 명시한 경우에만 실행한다. 해당 테스트는 격리 임시 DB를 사용하며 기본 `npm test`에서는 건너뛴다.

```sh
BUDGET_WORKBOOK='/절대/경로/원본.xlsx' npx vitest run tests/server/data.test.ts -t 'privately verifies supplied workbook'
```
