## 1. 적용 범위와 우선순위

**여러 가계부를 자유로운 트리로 구성하고, 선택한 가계부와 하위 전체 또는 가구 전체를 통합 조회하며, 공통 자산·결제수단·사용자 정의 태그를 사용하는 웹 가계부를 제공한다.**

2026-09-17 결정으로 고정된 메인과 한 단계 하위 구조를 대체한다. 아래의 메인·하위 예시는 일반적인 상위·하위 관계로 해석하며, 깊이 제한 없는 단일 부모 트리와 여러 최상위 가계부를 지원한다. 상세 계약은 [가계부 계위와 권한](./ledger-hierarchy.md)을 따른다.

원본 엑셀 분석을 출발점으로 하되, 이후 사용자가 정한 통합·제외·확장 사항을 우선한다. 기능 범위와 용어는 이 문서를 따르고, 구현 구조와 운영 조건은 시스템 구성 기준서를 따른다.

| 범위 구분 | 적용 기준 |
| --- | --- |
| 기본 기능 | 본문의 `F-` 기능 중 선택 기능으로 표시하지 않은 항목 |
| 선택 기능 | 금융 API 연동. 이용 가능 여부·비용·보안 확인 후 결정 |
| 후속 설정 | 조건에 따른 자산 배분 자동화. 고정 태그나 이름에 금액 효과를 내장하지 않으며 별도 설정·미리보기·변경 정책으로 설계 |
| 추가 검토 | 일괄 붙여넣기·일괄 수정·전월 항목 복사·월 정리 완료 표시·수정 잠금·분석 조건 저장 |

엑셀과 동일한 셀 배치나 서식을 복제하는 것을 목표로 삼지 않는다. PC·모바일에서 조회·탐색·입력하기 좋은 웹 화면으로 구성한다.

| 결제수단 | 거래에 사용한 카드·통장·현금 등의 수단 | 지출 귀속이나 자산 분류와 구분 |
| 태그 유형·옵션 | 사용자가 만든 분류 축과 그 안의 선택값 | 단일/복수 선택, 거래/자산 사용 위치, 가계부 적용 범위·순서·옵션 색상 관리 |
| 자산 배분 | 수입·지출에 반영할 자산별 금액 | 선택하지 않으면 자산 효과 없음. 배분하면 합계가 거래 금액과 일치해야 함 |
| 자산 변동 | 자산 사이 이동 또는 잔액 조정 | 가계부 수입·지출과 별도의 날짜·사유·작성자·금액 이력 |
| 저축 집계 | 저축 대상으로 명시한 자산에 유입·인출된 금액의 통계 | 거래 성격이 아니며 저장 당시의 집계값으로 계산 |
| 지출 귀속 | 누구를 위한 지출인지 나타내는 값 | 나·와이프·공동 |
| 입력·수정자 | 실제로 기록을 생성·수정한 사용자 | 로그인 정보에서 자동 기록 |

### 2.1 반드시 유지할 원칙

1. **가계부·예산·자산 항목은 독립적이다.** 이름이 같거나 목적이 비슷하다는 이유로 자동 연결하지 않는다.
2. **예비금은 일반 자산 항목이다.** 다른 자산 항목과 같은 체계로 관리하며 특정 목적의 예산 배정 기능으로 해석하지 않는다.
3. 가계부 생성·예산 설정·메인 연결만으로 자산 금액을 변경하지 않는다.
4. 거래는 하나의 소속 가계부에 한 번만 존재한다. 여러 화면에서 보여도 소비 지출은 한 번만 집계한다.
5. 가계부 거래 성격은 수입과 지출 두 가지다. 자산은 명시적인 거래 배분과 별도 자산 이동·조정으로 바뀐다.
6. 카드 구매를 소비 지출로 기록하고, 카드 청구 예정액·납부일은 별도 카드 정보로 보여준다.
7. 거래 원본과 연결된 자산 변동을 수정할 때는 기존 반영과 새 반영의 차이를 함께 처리한다.
8. 입력한 날짜와 실제 거래일을 구분한다. 월별 집계는 거래·자산 변동 각각의 실제 날짜를 기준으로 한다.
9. 태그 이름·옵션 선택·색상·순서·보관 상태만 바꿔서는 금액을 변경하지 않는다.
10. 최초 잔액과 잔액 조정은 수입·지출·저축 실적이 아니다. 저축 집계 대상 간 이동도 저축 실적을 늘리지 않는다.

### 4.1 연결 기본 동작

- 연결하면 기존 거래와 이후 거래를 메인 조회·집계에 포함한다. 부분 기간만 연결하는 기능은 현재 정의하지 않는다.
- 연결 해제는 메인 집계 범위를 바꾸는 동작이다. 하위 거래·예산·이력은 남고 실제 자산·카드 사용 내역은 사라지지 않는다.
- 재연결해도 거래나 자산 차감을 새로 생성하지 않는다.
- 하위 예산은 독립적으로 유지한다. 메인 예산에 자동 가산하지 않는다.
- 종료·보관과 연결 해제·삭제는 별개 동작이다. 보관 자체가 수정 잠금을 뜻하지 않는다.
- 메인과 하위의 연결 상태를 변경할 때 영향을 받는 집계 범위를 표시한다.
- 가계부마다 부모는 최대 하나다. 여러 최상위와 임의 깊이를 허용하되 자신·자손 아래 이동과 다른 가구 연결을 거절한다.
- 생성·이동·순서 변경·보관과 역할 변경은 관리자만 가능하다. 일반 사용자는 조회·원본 내역 편집·일반 설정과 예산 편집이 가능하다.
- 동시 구조 변경은 가구 전체 계위 버전으로 검사한다. 먼저 저장한 요청만 성공하며 나중 요청은 최신 구조 확인 후 명시적으로 재시도한다.
- 월·연도·설정 기간과 직접 기록만/하위 포함 범위를 선택한다. 상위 이동 시 그 노드의 분류 대응을 초기화해 새 부모 기준으로 다시 설정한다.

### 4.2 기간과 분류

활동 기간 밖의 예약·선결제도 해당 목적 가계부에 기록할 수 있다. 활동 기간이 10월 1~10일이고 항공권 구매일이 8월 15일이면, 여행 가계부에서는 여행 비용으로 보고 메인 월별 통계에서는 8월 거래로 집계한다.

하위의 `숙박·항공·식사`를 메인에서 `여행비`로 묶는 등 분류 대응을 설정할 수 있다. 대응되지 않은 거래도 총액에서 누락하지 않고 미분류 상태를 표시한다.

## 5. 거래 입력·조회

| ID | 기능 | 정의 |
| --- | --- | --- |
| F-TXN-01 | 거래 등록 | 수입·지출을 기록한다. 고정/일반 지출 등 필요한 분류는 사용자 정의 태그 유형과 옵션으로 표현하며, 자산 이동·조정은 별도 기록한다. |

| F-TXN-04 | 목록·검색·필터 | 기간·내용·분류·태그·결제수단·지출 귀속·가계부로 거래를 찾는다. |
| F-TXN-05 | 변경 이력 | 누가 언제 무엇을 바꿨는지 확인할 수 있는 기록을 남긴다. |
| F-TXN-06 | 캘린더 입력 | 목록/캘린더를 전환한다. 날짜 영역을 누르면 해당 날짜를 미리 입력한 새 내역 창을 연다. 일별 수입·지출 합계와 기존 내역을 조회하고 원본 내역을 열어 수정한다. |

캘린더는 선택한 달의 1일~말일을 표시하며 회계 집계 시작일과 구분한다. 가계부의 직접/하위 포함 조회 범위를 따르고, 전체 보기에서 날짜를 누르면 원본 가계부를 선택한 후 해당 날짜로 작성한다. 일반 사용자도 기록할 수 있다. 기존 내역 추가 초안과 날짜별 캘린더 초안은 분리해 다른 미완성 입력을 덮어쓰지 않는다. 모바일은 날짜별 합계와 건수에서 상세 내역을 열 수 있으며 날짜 버튼은 키보드로도 실행할 수 있다.

| 태그 | 유형별 단일 또는 복수 옵션 선택. 태그 자체에는 금액 효과 없음 |
| 자산 배분 | 자산별 양의 금액 목록. 배분이 있으면 합계는 거래 금액과 일치하며 같은 자산 중복 지정 불가 |
| 입력·수정자와 시각 | 서버에서 자동 기록 |

자산 배분은 선택 사항이다. 수입은 지정 자산을 늘리고 지출은 지정 자산을 줄인다. 수입·지출을 태그 이름으로 추정하거나 태그 선택만으로 자산을 차감하지 않는다. 거래의 배분 수정·삭제는 기존 효과를 교체하며 소비 거래를 추가로 만들지 않는다.

### 7.1 자산 금액과 이력

- 예비금은 일반 자산 항목이며 여행 예산과 독립이다. 예산 배정이나 이름 일치로 자동 연결하지 않는다.
- 현재 잔액은 최초 기준 금액과 유효한 자산 변동 합계로 계산한다. 현재 잔액을 맞출 때 최초 금액을 덮어쓰지 않고 목표 잔액과 당시 잔액의 차이를 조정으로 남긴다.
- 자산 이동은 서로 다른 두 자산 사이의 금액 이동이다. 가계부 수입·소비 지출을 생성하지 않는다.
- 조정은 평가·정정 사유를 기록하는 별도 이력이다. 수입이나 저축으로 대체 입력하지 않는다.
- 변동 취소 시 기록은 취소 상태로 남기고 잔액 효과를 제거한다. 거래 연결 변동은 원본 가계부에서 수정한다.
- 통장 관리 정보와 자산 항목이 같은 돈을 가리켜도 자산 합계에 중복 가산하지 않는다. 계좌 자동 잔액 반영은 별도 정책이다.
- 대출 조건은 수동 기록 기능이며 자동 상환계획·이자 계산을 기본 완료 조건에 넣지 않는다.

### 7.2 저축 집계

저축은 가계부의 세 번째 거래 종류가 아니다. 자산의 **저축 집계 여부**를 명시적으로 설정하고, 실제 변동을 저장할 때 저축 반영액을 함께 기록한다. 자산 이름이나 자산 태그로 추정하지 않는다.

| 발생한 변동 | 저축 실적 |
| --- | --- |
| 일반 자산 → 저축 집계 자산 | 저축 유입 |
| 저축 집계 자산 → 일반 자산 | 저축 인출 |
| 저축 집계 자산 → 저축 집계 자산 | 0: 이미 저축한 돈의 내부 이동 |
| 일반 자산끼리 이동 | 0 |
| 저축 집계 자산에 배분한 수입 / 지출 | 해당 금액의 유입 / 인출 |
| 최초 잔액 / 잔액 조정 | 0 |

순저축은 유입에서 인출을 뺀 값이다. 각 변동에 저장한 집계값을 합산하므로 태그나 현재 저축 설정 변경만으로 과거 실적이 바뀌지 않는다. 기존 거래에서 같은 자산의 금액을 고치면 당시 집계 여부를 유지하여 금액만 다시 반영한다. 새로 연결하는 자산에는 그 시점의 설정을 적용한다. 전체 변경을 소급 적용하는 자동 재분류는 제공하지 않는다.

### 9.1 유형과 옵션

유형은 분류 축이고 옵션은 그 안에서 고르는 값이다. 특정 이름·옵션·색상을 고정 기능으로 만들지 않는다. 기존 단일 `category` 문자열은 분류용 태그 유형의 옵션으로 옮긴다.

- 단일 선택 유형에서는 옵션을 최대 하나, 복수 선택 유형에서는 여러 개 선택한다.
- 유형·옵션의 순서와 이름·색상을 바꿔도 선택의 ID와 금액은 보존한다.
- 보관하거나 적용 범위를 줄이면 새 선택을 제한하되 기존 선택은 과거 내역에 남긴다.
- 삭제에 준하는 사용 중단은 보관으로 처리한다. 과거 참조를 파괴하는 영구 삭제는 별도 정책이다.
- 사용 중인 유형의 선택 방식 변경이 기존 선택과 충돌하면 이를 검증하며 과거 옵션을 조용히 제거하지 않는다.

### 9.2 분석과 금액 처리의 분리

태그 이름이나 옵션 선택은 자산·수입·지출·저축 금액을 자동 변경하지 않는다. 수입·지출의 자산 효과는 별도 배분 입력으로 정하고, 이동·조정은 자산 화면에서 기록한다. 초기 고정 태그와 네 가지 처리 규칙을 연결하던 모델은 폐기한다.

조건에 따른 자동 배분은 후속 설정 기능으로 설계한다. 채택 시 조건·대상·금액 미리보기와 충돌·소급 적용 정책을 별도로 정의하며, 사용자 정의 태그 관리가 이미 자동 배분을 제공한다는 뜻은 아니다.

### 10.1 집계의 일관성

- 전체 금액은 중복 없는 거래 기준으로 계산한다.
- 같은 유형 안의 선택 조건은 OR, 서로 다른 유형의 조건은 AND로 조합한다.
- 복수 선택 유형의 옵션별 금액 합계는 전체 고유 거래 합계보다 클 수 있으므로 구분하여 표시한다. 미분류 내역과 과거 보관 옵션도 분석에서 누락하지 않는다.
- 하위 항목과 메인 분류가 달라도 원본 금액은 변하지 않는다.
- 연결 자산별 조회는 자산에 반영된 금액과 거래 전체 금액을 구분한다. 일부 금액만 연결된 거래의 전체 금액을 해당 자산 사용액으로 오표시하지 않는다.
- 수입·지출은 가계부 거래, 저축은 자산 변동 통계, 이동·조정은 별도 자산 이력으로 계산한다. 자산 통계는 공동 공간 전체를 기준으로 하며 특정 가계부의 지출 합계와 범위를 혼동하지 않는다.
- 무지출 판정은 소비 거래를 대상으로 하며 원본의 고정지출 제외 기준을 태그 분류와 연결해 명세한다. 수입과 자산 이동·조정은 소비로 계산하지 않는다.

선택 표시는 잠금이 아니다. 현재 충돌 검사의 설계 기본안은 거래 행 단위이며 같은 행의 다른 필드도 충돌할 수 있다. 글자 단위 병합은 제공하지 않는다.

저장 성공을 확인하기 전에는 완료로 표시하지 않는다. 응답 유실 후 재전송하거나 재접속해도 거래와 자산 변동이 중복 생성되지 않아야 한다. 구체적인 복구·인증·세션 조건은 시스템 구성 기준서를 따른다.

## 14. 대표 사용 시나리오

### 14.1 목적별 가계부를 메인에서 조회

1. 여행 가계부를 만들고 예산 30만 원과 숙박·교통·식사 항목을 설정한다.
2. 여행 가계부에서 식사 8만 원을 기록한다.
3. 여행 가계부에 지출 8만 원과 남은 예산 22만 원이 표시된다.
4. 메인에 연결하면 메인 지출에도 같은 거래가 한 번 포함된다.
5. 메인에서 해당 거래의 편집을 선택하면 여행 가계부의 원본으로 이동한다.
6. 별도의 자산 배분을 입력하지 않은 이 과정에서는 자산 금액을 변경하지 않는다.

### 14.2 명시적으로 지정한 자산 항목 반영

1. 자산 관리에 예비금 50만 원을 기록한다.
2. 메인 가계부에서 생활 지출 2만 원을 입력한다.
3. 자산 배분에서 예비금에 2만 원을 명시한다.
4. 소비 지출은 2만 원, 예비금은 48만 원으로 표시된다.
5. 거래를 1만 원으로 수정하면 소비 지출은 1만 원, 예비금은 49만 원이 된다.
6. 두 자산에서 나눠 부담하려면 각각의 배분 금액을 지정하고 합계를 거래 금액과 맞춘다.

### 14.3 카드 청구 정보 확인

1. 카드 구매 거래 5만 원을 기록한다.
2. 가계부 지출은 5만 원으로 집계된다.
3. 카드 화면에는 이 거래가 해당 이용 기간의 예상 청구액에 반영되고 납부 예정일이 표시된다.
4. 청구 정보가 계산되거나 표시되어도 가계부에 추가 지출 5만 원을 생성하지 않는다.

### 14.4 자산 이동과 잔액 조정

1. 생활 자산에서 저축 집계 자산으로 10만 원을 이동하면 가계부 수입·지출은 그대로이고 저축 유입은 10만 원이다.
2. 저축 집계 자산끼리 다시 이동하면 저축 유입·인출을 추가로 늘리지 않는다.
3. 현재 잔액 49만 원을 실제 확인 금액 50만 원으로 맞추면 +1만 원 조정과 날짜·사유·작성자를 남긴다. 수입·지출·저축 실적은 변하지 않는다.
4. 태그 이름이나 저축 집계 설정을 바꿔도 이미 기록한 저축 실적을 다시 계산하지 않는다.

| 분류·태그 | 유형/옵션과 단일/복수 선택·거래/자산 위치·가계부 범위는 기준 확정. 원본 대분류/소분류와 예산의 상세 대응은 후속 정의 |
| 카드 예상 청구 | 이용 기간, 결제일, 할부·취소·이월·조정, 실제 납부의 계좌 반영 여부 |
| 가계부 생명주기 | 비어 있지 않은 가계부의 삭제·복구와 데이터 보관 정책 |
| 연결 구조 | 한 단계·부모 하나의 초기 기본안을 상세 모델에 반영; 다단계·다중 부모는 별도 확장 |
| 데이터 출력 | XLSX 출력 지원 및 서식 수준, 장기 백업 보관 방식 |
| 화면 상세 | 메뉴·레이아웃·모바일 입력 방식·저장 완료 시점별 조작 |

### 17.1 추가 제안으로 남겨둔 기능

- 여러 행 붙여넣기와 일괄 수정
- 전월 고정 항목 복사
- 월 정리 완료 표시와 완료한 달의 수정 잠금
- 사용자 지정 분석 조건 저장
- 반복 거래 자동 생성·결제일 알림
- 개인 전용 비공개 가계부, 제3자 공유, 다단계·다중 부모 연결
