# UI/UX 개선 기준

기준일: 2026-09-17. 기존 기능·데이터 모델·금액 계산·API·저장 방식은 유지하고, 화면의 정보 구조와 조작 경험을 개선한다.

현재 시각 기준은 [우가 디자인시스템](./uga-design-system.md)이다. 아래의 정보 구조·조작·접근성 규칙은 유지하며, 이전 회색·파랑 테마는 우가의 크림·브라운·코랄 토큰과 캐릭터 기반 SVG로 대체했다. 이전 검증 기록은 당시 커밋의 결과이며, 이번 브랜드 적용 결과는 우가 디자인시스템 문서에 구분해 기록한다.

## 2. 화면별 개선

### 현재 탐색 구조: 가계부 방에서 시작

- 기본 진입은 메신저형 가계부 목록이다. 기존 Uga 아이콘·색상·공통 컴포넌트를 사용하고, 방 이름·최근 수정 내역·하위 포함 기록 수를 한 행에 표시한다. 최상위 방에서 시작하며 검색은 하위 경로까지 포함한다. 보관한 부모 아래의 활성 방과 부모 없는 방도 접근할 수 있다.
- 방 안에는 현재 가계부 이름·상위 경로·선택 보기를 나타내는 고정 헤더와 목록/캘린더/통계/계획·일정 전환을 둔다. 방을 바꾸려면 목록이나 하위 가계부로 이동한다. 통계·계획의 가계부 범위는 현재 방에 고정하고, 하위 포함 여부·기간 등 세부 조건은 각 화면에서 조절한다.
- 자산·카드/통장·태그·데이터 관리는 `우리 집 공통`으로 표시한다. 통계의 순저축은 가구 전체 기준이며, 계획은 원본 가계부별로 보관한다. `전체 가계부`는 원본 기록을 모아 보는 집계 화면이다.
- 모바일에서는 방 이름과 네 개 보기 버튼을 상단에 유지하고, 가계부 목록·내역 추가·더보기를 하단에 둔다. 새 가계부와 하위 가계부 생성은 기존 관리자 권한을 따른다. 모바일 전체 메뉴와 데스크톱 트리에서 계위 관리에 계속 접근할 수 있다.
- 가계부·보기·조회 월을 URL로 복원하고, 목록/캘린더 선택은 브라우저의 계정·가계부별 설정으로 기억한다. 기존 데이터·공동 접근 권한·계위 변경 동시성 계약은 유지한다. URL 상태의 단위 검사와 실제 탐색·입력·모바일 회귀 검증은 분리해 기록한다.

| 화면      | 문제                                                        | 개선                                                                          |
| --------- | ----------------------------------------------------------- | ----------------------------------------------------------------------------- |
| 공통      | 작은 글자, 흐린 색, 중복 제목·장식, 화면마다 다른 입력 방식 | 공통 색·크기·간격·표면·입력·버튼 규칙, 큰 핵심 금액, 명확한 선택 상태         |
| 가계부    | 요약과 설명이 거래 목록을 아래로 밀어냄                     | 월 요약 후 거래 목록, 넓은 화면의 보조 예산·분류 영역, 모바일 행 카드         |
| 자산      | 기준 잔액·이동·관리 정보가 같은 위계                        | 순자산·현재 잔액 우선, 관리 정보와 월별 수치의 단계적 공개                    |
| 카드·통장 | 큰 장식 카드와 긴 세부 정보                                 | 예상 대금·납부일·연결 잔액 우선, 이름 옆 설정, 상세 정보 펼치기               |

## 3. 공통 규칙

- `brand/tokens.css`에서 시각 토큰을, `design-system.css`에서 호환 변수와 주요 공통 컴포넌트를 관리한다. 입력·선택 동작은 아래 자체 컴포넌트로 조립하고, 화면 고유 스타일은 각 화면의 CSS에 둔다.
- 기본 본문은 15~~16px에 대응하는 크기, 중요한 숫자는 24~~40px 위계, 주요 조작은 최소 44px 영역을 사용한다.
- 보조 문구와 장문의 집계 기준은 핵심 결과보다 낮은 위계로 배치하되 필요한 정보에 접근할 수 있게 한다.
- 새로운 거래·기존 수정·저장 실패·충돌·재시도의 동작은 유지한다. 폼에서 금액과 내용을 먼저 보여주며 저장 옵션과 작성 정보는 뒤에 둔다.
- 탭 전환으로 작성 중 입력을 잃지 않도록 필요한 패널을 유지한다. 탭·접기·필터의 현재 상태를 접근성 속성으로 알린다.
- 키보드 초점, native dialog의 초점 제한·Escape, 줄바꿈, 작은 화면, `prefers-reduced-motion`을 유지한다.
- 거래 필터와 공동 자산 통계의 범위 차이, 카드 예상액의 의미, 원본 검토 자료와 확정 기록의 차이는 설명을 유지한다.

## 4. 자체 입력 컴포넌트

브라우저 기본 선택창·날짜창·색상창을 쓰면 닫힌 입력만 꾸며지고, 실제 조작 중에는 서로 다른 UI가 나타난다. 가계부·자산·카드/통장·통계·계획·태그·데이터 화면과 편집창에서 열린 상태까지 같은 규칙을 적용한다.

| 컴포넌트                   | 적용과 동작                                                                                                                        |
| -------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| `Popover`                  | 화면 경계에 맞춰 위/아래 위치 조정, 편집창 안에서도 잘리지 않는 최상위 레이어, 바깥 클릭·Escape·초점 복귀                          |
| `SelectField`              | 공통 선택 버튼·옵션 목록·체크 표시·그룹·검색, 키보드 이동, 필수값·비활성화 상태                                                    |
| `DateField` / `MonthField` | 자체 날짜 달력·월 그리드, 연도/월 이동, 오늘/이번 달, 선택 해제, 최소/최대 날짜, 키보드 이동                                       |
| `TagBadge` / `TagFields`   | 저장한 색상을 바탕으로 옅은 배경·읽기 쉬운 글자색, 단일/복수 선택·해제·검색·옵션 생성. 거래·자산·통계·계획·설정에서 같은 뱃지 사용 |
| `ColorField`               | 선택 색상 미리보기와 HEX 입력. 기존 색상 프리셋과 임의 색상 지정 유지                                                              |
| `FileField`                | 공통 파일 선택 버튼·파일명 표시·키보드 초점. XLSX/CSV/JSON 탭 전환 시 선택 파일 보존                                               |
| `Tooltip`                  | 아이콘·태그·그래프의 자체 도움말, 마우스와 키보드 초점 지원, Escape/클릭으로 닫기, 화면 경계에 맞춘 위치                           |
| 공통 CSS / `Dialog`        | 체크박스·라디오·숫자 입력·접기 화살표·오류 안내·hover/focus/disabled 상태 통일                                                     |

- 팝업은 [Popover API](https://developer.mozilla.org/en-US/docs/Web/API/Popover_API/Using)의 top layer에 자체 DOM/CSS를 표시한다. OS 선택 UI나 외부 UI 라이브러리를 가져오지 않는다.
- 태그 유형·상하위 관계·보관·색상 저장값은 유지한다. 뱃지 배경과 글자색만 표시 시 계산하며 일반 크기 글자의 대비를 확보한다.
- 팝업 안에서 초점을 옮기는 동안 같은 필드를 편집 중인 것으로 처리한다. 필드를 떠날 때의 자동 저장과 상대방에게 보이는 날짜·결제수단·태그 선택 위치를 유지한다.
- 새 입력을 추가할 때 직접 `select`, `input[type=date/month/color]`나 기본 `title` 툴팁을 만들지 않는다. 필수값 검증, 접근 이름, 키보드, 작은 화면의 열린 상태까지 공통 컴포넌트를 사용한다.

## 5. 검증

기존 단위/API 검사로 금액 계산과 저장 계약을 확인하고, 실제 바뀐 탐색 경로를 반영한 브라우저 테스트로 등록·수정·공동 사용·충돌·이관·복원 흐름을 검사한다. 데스크톱과 390/320px에서 화면을 확인한다. 시각적 개선의 정량적 사용성 효과는 실제 두 사용자의 사용 후 평가 대상이며, 테스트 통과만으로 사용성 지표가 향상됐다고 주장하지 않는다.

### 최신 실행 결과 (`5c06847`)

- `npm run check`: TypeScript·단위/API 156개·프로덕션 빌드 통과. 개인 원본 파일이 필요한 선택 테스트 1개는 제외.
- `npm run test:e2e`: 전체 24개 통과. 기존 19개 흐름에 자체 선택창·날짜·태그·모바일 팝업·툴팁 검증 5개를 추가했다.
- PC와 320/390px 주요 7개 화면 및 거래 편집창에서 기본 select/date/month/color/title UI가 남지 않았는지 검사했다.
- 선택·검색·Escape·바깥 클릭·초점 복귀, 편집창 안의 팝업, 달력의 키보드 이동·연도 변경, 선택한 단일/복수 태그 저장과 뱃지 색상 일치를 확인했다.
- 두 사용자 편집 위치 공유에 달력·결제수단 팝업을 포함했고, 자동 저장·충돌·응답 유실·자산 이동·카드 예상액·통계·XLSX 이관·JSON 복원 검증을 유지했다.
- 파일 선택 입력의 접근 이름과 파일명 중복 표시를 수정했다. 데이터 탭을 바꾼 뒤 CSV 열 대응·원본 ID·CSV/JSON 선택 파일 보존 검사를 통과했다.
- `output/playwright/design-*.png`, `controls-*.png`에서 일반 화면과 열린 메뉴·달력·태그·툴팁을 시각 확인했다. 모두 합성 데이터이며 Git에는 포함하지 않는다.
- 서버·공유 계산·실시간 서버·스키마·의존성 변경 없음. 기존 로컬 가계부와 원본 Excel은 변경하지 않았다.

### 이전 UI 개편 실행 결과 (`c19640c`)

- `npm run check`: TypeScript, 단위/API 156개, 빌드 통과. 개인 원본 파일을 필요로 하는 선택 테스트 1개는 제외.
- `npm run test:e2e`: 전체 19개 통과. 기존 계산·저장·태그·계획·이관·충돌 검증을 유지하고 바뀐 화면 탐색 경로를 반영했다.
- 최종 월 선택 너비·모바일 편집창 너비·제목 줄바꿈 보정 후 타입 검사와 디자인 E2E 3개를 다시 통과했다. 이 실행도 웹 앱을 다시 빌드한다.
- 320px·390px에서 전체 메뉴 접근, 목적 가계부 선택/추가 접근, 페이지 가로 넘침, Escape 후 메뉴 버튼 초점 복귀, 편집창 너비를 검사했다.
- 데이터 탭 전환 후 CSV 텍스트·열 대응·선택 파일과 JSON 선택 파일이 유지되는지 확인했다.
- PC/모바일 주요 7개 화면과 거래 편집창의 스크린샷 16개를 `output/playwright/design-*.png`에 생성하고 시각 검토했다. 합성 데이터이며 Git에는 포함하지 않는다.
- 서버·실시간 서버·공유 계산·스키마·의존성 변경 없음. 원본 Excel과 기존 로컬 가계부 자료를 변경하지 않았다.
