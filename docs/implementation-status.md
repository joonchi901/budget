- 거래·자산·카드 원본은 이동하지 않는다. 분류 대응은 각 부모 관계에 적용하며 부모 변경 시 해당 노드의 기존 대응을 초기화한다. 정확한 연간 예산이 없으면 연간 예산 미설정으로 표시한다.
- 가계부 화면에 목록/캘린더 전환을 제공한다. 날짜를 누르면 해당 날짜가 입력된 새 내역 창이 열리고, 기존 거래는 원본 가계부에서 편집한다. 전체 보기에서 추가할 때는 기록할 원본 가계부를 먼저 선택한다.
- 캘린더는 회계월 시작일과 별도로 매월 1일~말일을 표시하며 날짜별 수입·지출·기록과 월 합계를 제공한다. 모바일에서는 일별 상세 창을 사용한다. 날짜별 작성 초안은 일반 추가 초안과 분리하고 보관한 가계부에는 추가할 수 없다.
- 로컬·운영 DB에 migration `0012_hierarchy_roles.sql` 적용 완료. 적용 전 운영 SQL 백업을 Git 제외 경로에 저장했다. 데모 seed를 다시 실행하거나 기존 금융 기록을 초기화하지 않았다.
- `npm run check`: 타입 검사·빌드 성공, 17개 파일 **184개 통과·1개 선택 제외**. 제외 항목은 비공개 원본 엑셀 opt-in 테스트다. 합성 자료 백업/복원·동시성·권한·집계는 실행했다.
- 브라우저 기존·계위 27개는 전체 실행 26개 성공 후 통계 직접 기록 필터를 수정하여 통계·계위 4개를 재검증했다. 캘린더 추가 후 관련 19개 실행 중 16개 성공, 신규 테스트 로그인 선택자 수정 후 캘린더 3개·기존 거래 5개를 다시 실행해 **8개 모두 성공**했다. 초안 보존·하위 원본 편집·편집 위치 전송·윤년·320/390px·보관 상태를 포함한다. 한 번의 전체 30개 실행 결과로 합산하지 않는다.
- 운영 주소: [우리의 가계부](https://our-budget-production.our-budget.workers.dev). 당시 Worker 버전 **`9e2ff1ef-db3c-4768-b73d-d11df5c64af2`**. `deploy:preview`와 `deploy:production` 성공, `check:production --configured`에서 HTTPS·Google 로그인 설정·비로그인 API 차단·데모 로그인 차단을 확인했다.
- 읽기 전용 운영 D1 조회에서 `u1=admin`, `u2=user`, `hierarchy_version=1`을 확인했다. 운영 Chrome의 기존 본인 로그인 세션에서 새로고침 후 트리·구성원 권한 표시·실시간 연결·캘린더를 확인했다. 9월 17일을 눌러 날짜가 `2026년 9월 17일`인 입력창을 확인하고 저장 없이 닫았다. 운영 테스트 거래는 생성하지 않았다. 배우자 실계정의 기기 간 공동 편집은 아직 별도 확인이 필요하다.
- 배포는 기존 Uga 디자인 변경이 포함된 작업 트리를 기준으로 수행했다. 배포 소스/산출물 172개 파일의 SHA-256 목록은 Git 제외 경로 `.wrangler/hierarchy-calendar-release-manifest.json`에 보관했다(목록 파일 SHA-256 `598ff78110a745de179f4e5a6fb84546c649fa2f640543623927bdafbcc47e61`). 기존 미커밋 디자인과 이번 기능의 커밋 분리 확인은 사용자 응답 대기 중이며, 이번 변경의 커밋·push 완료를 뜻하지 않는다.

- 공개 주소: [https://our-budget-production.our-budget.workers.dev](https://our-budget-production.our-budget.workers.dev).

배우자 기기의 로그인과 실제 2인 공동 동작은 확인 요청 후 응답 대기 중이다. 본인 로그인과 실시간 연결만으로 2인 공동 편집 성공을 주장하지 않는다. 기존 로컬 검증 수와 구현 커밋은 위 표에 당시 기록 그대로 유지한다.

## 4. 운영 전 남은 사항

1. [운영 로그인 설정](./auth-deployment.md)의 Google OAuth·secrets·두 계정 허용목록 등록은 완료했다. 남은 사용자 확인은 배우자 기기의 실제 로그인과 두 계정의 공동 동작이다. Gmail이 아닌 Google 계정도 허용하지만 별칭·전달 주소를 자동 변환하지 않으므로 ID token이 실제 반환하는 `email`과 일치해야 한다. 비밀값을 Git이나 채팅에 넣지 않는다.
2. 본인 로그인·실시간 연결·새로고침·로그아웃·재로그인과 `--configured` 공개 검사는 통과했다. 두 기기 공동 편집·재접속·세션 만료, 원격 사용량/성능/장기 미사용은 아직 실측하지 않았다.
3. 실자료 반영 전에 결제수단·자산의 실제 대응을 확인한다. 날짜/분류가 불완전한 46행, 유효하지만 자산 연결이 없는 저축 16행, 예비금·가족행사 메모 등은 자동으로 확정하지 않는다.
4. JSON 백업을 개인 저장 공간에 보관하고 복원 절차를 운영 환경에서도 확인한다.
5. GitHub 개인 인증 만료로 원격 push를 보류했다. 별도 GitHub CLI 프로필에서 개인 계정 device flow 승인을 요청했으며, 기존 회사 계정은 사용하지 않았고 push는 아직 실행하지 않았다.

금융 API는 선택 기능이며 제공자를 연결하지 않았다. 태그 조건 자동 배분, 일괄 붙여넣기/수정, 월 마감 잠금, 저장된 분석 조건은 기존 정의서의 후속/추가 검토 범위를 유지한다. 카드 할부·취소·이월·휴일 보정, 금융기관 확정 청구 대사는 현재 자체 예상액 계산에 포함되지 않는다.
