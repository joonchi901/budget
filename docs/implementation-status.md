## 2. 현재 돈·분류 모델의 기준

- 가계부 거래는 수입과 지출이다. 저축·이체를 거래 버튼이나 소비 합계에 다시 넣지 않는다.
- 태그 이름·옵션·색상·순서·보관은 금액을 바꾸지 않는다. 명시적 자산 배분과 별도 자산 이동·조정만 효과를 만든다.
- 잔액 맞추기는 기준 잔액 덮어쓰기가 아니라 당시 차액과 사유를 기록하는 자산 변동이다.
- 최초 잔액·조정·저축 집계 자산 간 이동은 저축 실적 0이다. 과거 저축은 저장한 값으로 계산하며 현재 태그·설정으로 소급 변경하지 않는다.
- 가계부·예산·예비금을 자동 연결하지 않는다. 카드 청구 정보도 새 지출을 만들지 않는다.
- 현재 저장 버튼·브라우저 닫기 경고를 사용하며 입력 완료 자동 저장은 후속 필수다. 브라우저 종료 후 초안 복원은 미구현이다.

## 3. v2 최신 검증 기록

2026-09-16 로컬 가상 데이터로 확인했다. 기능·검증 코드 커밋은 `64c2483`이다. 아래 결과는 이번 모델 개편에 대한 검증이며 전체 기능 정의서나 실제 운영 환경의 완료를 뜻하지 않는다.

| 명령 / 시나리오 | 최종 결과 |
| --- | --- |
| `npm run check` | 타입 검사 → Vitest → Vite 빌드 모두 통과. 서버 28개 + 공유 계산 19개 = 47/47 |
| 서버 최종 호환성 확인 | 서버 28/28 및 타입 검사 재통과. v1 최대 80자 한글 분류가 긴 태그 ID로 이관된 뒤 거래 수정에도 유지됨 |
| `npm run test:e2e` | Chromium 5/5 통과, 12.0초. 두 사용자 협업, 태그 관리·명시 배분·자산 이동/조정·저축 유입/인출 검증 |
| 응답 누락·재전송 | 거래 저장·입력 중 태그 생성·자산 이동의 응답 누락 후 재시도가 중복 저장을 만들지 않음 |
| 앱 내부 v1→v2 전환 | 로컬 `0002` 마이그레이션 23개 SQL·예시 시드 9개 SQL 적용. 이전 거래 5건과 자산 잔액 5개를 백업과 직접 대조해 동일함을 확인. 테스트에서 분류·변동 이력·기존 저축 의미 보존 확인 |
| 태그·자산 정합성 | 버전 충돌, 원자적 저장·롤백, 배분 합계, 조정 차액, 저축 스냅샷 보존, 보관 참조 확인. 태그 100개·배분 30개 및 가계부 범위 100개 입력 검증 |
| PC·모바일 | 1440px 데스크톱·390/320px 모바일의 주요 화면을 브라우저 검사. 자산·태그·입력 화면 스크린샷도 육안 확인 |
| 개발 실행 | 기존 로컬 DB를 전환한 뒤 Vite 5173·Worker 8787 실행 확인 |

실행 환경은 Node.js 24, 로컬 Miniflare Worker·D1·SQLite 기반 DO를 기본으로 한다. E2E는 [스크립트](../scripts/e2e.mjs)의 별도 임시 DB와 Worker 8790에서 수행하며 개발 DB를 사용하지 않는다.

실제 OIDC·원격 배포·원격 비용과 성능·장기 백업 복원은 검증하지 않았다. 알림 없이 만료된 WebSocket의 전송 계층 종료 이벤트가 완료되는 정확한 시점도 확정하지 않았다. 세션 만료 후 HTTP 접근·변경 알림 차단과 명시 로그아웃 연결 종료의 검증과 구분한다.

## 4. 과거 기록 — v1 초기 구현 스냅샷

**아래는 모델 개편 전 초기 구현의 기록이며 현재 코드의 검증 결과가 아니다.** 2026-09-16 기준 가상 데이터로 확인했다.

| 초기 검증 | 당시 결과 |
| --- | --- |
| 타입 검사·Vite 빌드·`npm run check` | 통과 |
| Vitest | 서버 17개 + 공유 계산 12개 = 29/29 통과 |
| Chromium E2E | 초기 시나리오 3/3 통과, 6.9초 |
| 화면 | 당시 1440px 데스크톱·390/320px 모바일 주요 화면·입력 폼, pageerror 0, 주요 스크린샷 확인 |
| 저장·협업 | 동시 수정, 자산 효과 교체, 원자적 롤백, 응답 누락 재전송, 원본 이동, 연결 변경, 오프라인 복귀 확인 |
| 개발 실행 | 당시 로컬 D1 초기화·가상 시드와 Vite 5173/Worker 8787 실행, 재실행 시 기존 값 보존 확인 |

초기 검사에서 세션 만료의 HTTP 접근·변경 알림 차단과 명시 로그아웃 연결 종료는 확인했다. 알림 없이 만료된 소켓의 전송 계층 종료 이벤트 완료 시점은 지연이 관측돼 미검증으로 남겼다. 이 경계도 변경된 코드의 최종 검증과 구분한다.

## 5. 후속 필수·선택 범위

- 실제 OIDC·두 계정 등록, 운영 세션 정책, 원격 배포·성능·비용·장기 미사용 검증.
- 자동 저장, 전체 예산 편집·목표·월급 배분·행사/경조사·대출 조건·자산 월별 추이·무지출 달력·전체 분석.
- 카드/통장 관리 설정, 금융기관 확정 청구와 다른 자체 예상액의 할부·취소·이월·휴일 처리.
- 원본 Excel 이관, 내보내기, 장기 백업·복원, 영구 삭제·보관 정책, 전체 변경 이력.
- 조건에 따른 자산 배분 자동화는 후속 설정이다. 현재 태그 CRUD가 자동 돈 처리를 제공한다는 뜻은 아니다.
- 금융 API는 선택 기능이다. 일괄 붙여넣기·월 마감 잠금·저장된 분석·다중 부모 연결은 추가 검토 상태를 유지한다.
