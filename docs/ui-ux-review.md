# 전체 화면 공통화와 UI/UX 점검

기준일: 2026-09-18

## 결과와 범위

로그인, 가계부 목록·거래·캘린더, 자산, 카드·통장, 통계, 계획, 태그, 데이터, 설정을 동일한 기본 컴포넌트로 조립했다. 화면과 편집창·패턴을 포함한 19개 실제 소스를 [화면 목록](../src/stories/screens.json)으로 관리한다. 화면마다 같은 모양의 별도 버튼·폼을 만드는 방식으로 돌아가지 않도록 정적 검사와 CI를 확장했다.

금융 계산, 수입·지출과 자산 이동의 구분, 가계부 계위·원본 수정 규칙, 결제수단 미지정, 관리자/사용자 권한, 기기 초안과 실시간 편집 계약은 유지한다. 검증은 손으로 만든 Storybook 자료와 매번 생성하는 임시 로컬 D1을 사용한다. 운영 DB나 사용자의 원본 Excel을 테스트 자료로 가져오지 않는다.

## 발견해서 수정한 문제

### 입력과 저장

- 미저장 설정을 닫을 때 확인 없이 입력이 사라지던 동작을 `Dialog dirty`·`CloseButton`으로 통일했다. 계속 작성하면 입력과 포커스가 유지된다.
- 중첩된 취소 확인창을 함께 닫으면 포커스가 페이지 본문으로 빠지던 문제를 수정했다. 연결된 원래 열기 버튼으로 복귀한다.
- 거래 입력은 기기 초안 보관을 유지하며, 브라우저 저장 실패 때만 닫기 전 입력 손실을 확인한다.
- 공백만 있는 가계부 이름과 시작일보다 이른 종료일을 저장 전에 차단한다.
- 잘못된 CSV를 다시 선택해도 이전 검사 결과와 적용 버튼이 남던 문제를 수정했다. 새 파일·매핑·대상이 바뀌면 검사를 다시 해야 한다.
- 손상된 백업 구성원 정보로 화면이 중단되지 않도록 파일 검증과 오류 안내를 보강했다.
- 데이터 상태가 변경된 뒤 이전 엑셀 미리보기로 적용하지 못하도록 차단했다. 엑셀 처리·결과 확인 중에는 부모 데이터 탭과 검토 바로가기도 함께 잠그고, 요청이 확정되면 해제한다.
- 태그와 자산 충돌 재조회에서 상위 옵션과 변경 기준값을 빠뜨리던 문제를 수정했다. 가계부 설정도 서버에서 수용한 계위·보관 상태의 변경 기준만 갱신해 다른 작성 내용은 유지한다.
- 상대방의 실시간 권한 갱신을 내 작성 내용으로 오인하지 않도록 미편집 값은 최신 상태를 따르고 실제 초안만 별도로 보관한다. 구성원 권한을 하나 저장해도 다른 작성 내용이 남도록 했다. 실시간으로 마지막 관리자가 된 경우 기존 일반 사용자 초안의 저장도 차단한다.

### 배치와 접근성

- 공통 입력·버튼·탭·폼·패널·도구모음·요약 격자를 전 화면에 적용했다.
- 좁은 표에 이름이 있는 `TableScroll`을 적용해 키보드로 가로 스크롤할 수 있다.
- 탭을 방향키·Home·End로 선택하고, 비활성 옵션은 건너뛴다.
- 자산 태그 내부에 일반 span 배경·여백이 번지던 CSS 선택자를 수정했다.
- 데이터/계획 탭, 보관된 계획, 거래 귀속 배지의 글자 대비를 개선했다.
- 모바일 계획 탭을 3+2로 배치하고, 320px 거래 카드의 금액·수정 버튼과 로그인 여백을 정리했다.
- 공통 버튼 도입으로 월별 차트 막대의 정렬이 달라지지 않도록 전용 세로 배치를 유지했다.

## 재현과 검증

```sh
npm run check
npm run check:ui
npm run test:e2e
```

`check:ui`는 소스·명세 등록 검사, Storybook 정적 빌드, 모든 상태의 Chromium 조작/WCAG 2 A·AA/2.1 AA/가로 넘침 검사를 320·390·1440px에서 실행한다. `test:e2e`는 계정·내역·역할·공동 편집·데이터 가져오기를 임시 로컬 DB로 검증한다. 실제 Escape, 미저장 입력 유지·버리기·포커스 복귀와 잘못된 CSV 교체는 전용 회귀 검사로 추가했다.

로컬 검증 결과:

- TypeScript, 제품 빌드, Storybook 빌드, 소스·명세 경계 검사 통과
- 단위 테스트 235개 통과, 선택적 원본 XLSX 검사 1개 제외
- 전체 앱 E2E 55개가 최종 코드 기준 단일 실행에서 통과(1.8분)
- Storybook 225개 상태 × 320·390·1440px = 675회 조작·접근성·가로 넘침 검사 통과
- 마지막 데이터 카드 배치 수정 뒤 해당 22개 상태를 세 너비에서 추가 확인

자동 저장 시간 검사는 설치된 Playwright 가상 시간이 실시간으로도 진행되면서 799ms 검사 전에 800ms를 넘던 불안정성을 수정했다. 시간을 명시적으로 정지한 뒤 기존 799/801ms 경계와 동일 요청 재사용 검증을 유지한다. 제품의 자동 저장 간격은 바꾸지 않았다.

자동 접근성·넘침 검사와 주요 화면 시각 검사를 함께 사용하며, 자동 검사가 모든 보조공학·OS·브라우저 조합의 사용성을 보증하지는 않는다. 현재 브라우저 자동화 기준은 Chromium이다.

## 유지 관리

새 화면/편집창은 [UI 컴포넌트 체계](./ui-component-system.md)에 따라 같은 커밋에 실제 컴포넌트 Story와 화면 목록을 추가한다. 공유 컴포넌트에서 의미와 기본 동작을 관리하고, 도메인 CSS는 표·차트·달력 등 해당 정보의 배치를 담당한다. 모든 DOM을 같은 Grid로 감싸거나 모든 기존 CSS를 없애는 것이 공통화의 기준은 아니다.

CI에는 전체 앱 E2E를 포함했다. 운영 배포와 Cloudflare 데이터 변경은 이번 로컬 UI 검증의 일부가 아니다.
