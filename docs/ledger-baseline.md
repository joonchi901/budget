# 가계부 재설계 기준

기준일: 2026-11-02. 재설계의 제품·데이터·화면 기준이다. 컴포넌트 계위와 Storybook 규칙은 [UI 컴포넌트 체계](./ui-component-system.md), 시각 기준은 [우가 디자인시스템](./uga-design-system.md)을 따른다. 이전 앱은 Git 기록 `d3509d5`에 있다.

- **확정**: 사용자가 결정한 사항
- **기본값**: 별도 결정 전까지 따르는 추천안. 바꾸면 이 문서를 먼저 고친다.

## 1. 목표

관리가 복잡했던 이전 앱을 초기화하고 **가계부 본연의 기능을 먼저 완성**한다. (확정)

1. **내역 추가**: 버튼 하나로 가계부에 정의된 필드를 입력하거나 태그를 고른다. Notion 데이터베이스 속성과 같은 방식이다.
2. **적재와 보기**: 가계부 기간 단위로 표·캘린더에 쌓아 보기 쉽게 보여준다.
3. **통계**: 태그(선택형 필드) 단위로 집계한다.

이전 설계에서 유지한다. (확정)

- **묶음**: 여러 가계부를 모아 상위 보기·통계를 만든다. 예: 11월·12월·1월 → 2026, 일본여행 → 여행.
- **방**: 메신저처럼 가계부 목록에서 골라 들어간다.

이번 범위에서 제외한다: 자산·저축 반영, 카드 청구, 계획·예산, 엑셀 이관, 관리자/일반 권한, 무한 깊이 트리와 계위 버전 충돌 처리, 실시간 동시 편집.

## 2. 참고 샘플: Notion "2026 가계부"

- 한 달은 월급날부터 다음 월급날 전날까지다(예: 10/23~11/22). 수입은 월급날, 지출은 다음 날부터 적는다.
- 열: 날짜, 수입·고정지출·지출(각각 이름과 금액), 결제방식(카드·자동이체), 카테고리(단일 선택), 누가(다중 선택, 비어 있으면 공동), 비고.
- 이름은 `무엇_어디서` 형식이다. 예: `장보기_쿠팡`.
- 고정지출은 결제수단이 아니라 매달 나가는 돈인지로 구분한다. 관리비는 카드로 내도 고정지출이다.
- 바람: 신용카드 결제일·자동이체일을 정리해 접어 두고, 자동이체 날짜를 정리해 매번 여러 날을 확인하지 않는다.

## 3. 데이터 모델

타입과 검증·합계 함수는 [src/shared/ledger.ts](../src/shared/ledger.ts), 합성 데이터는 [src/stories/fixtures.ts](../src/stories/fixtures.ts)에 있고 Storybook `00 Guide/데이터 모델`에서 확인한다.

| 개념      | 내용                                                                   |
| --------- | ---------------------------------------------------------------------- |
| 가계부    | 방 하나. 이름, 기간(시작~종료), 아이콘, 필드 정의, 태그 옵션을 가진다. |
| 필드 정의 | 가계부별 param. 고정 필드와 사용자 필드로 나뉜다.                      |
| 태그 옵션 | 선택형 필드의 옵션. 가계부별로 이름·색·순서·보관 상태를 가진다.        |
| 내역      | 정확히 한 가계부에 속한다. 고정 필드 값과 사용자 필드 값을 가진다.     |
| 묶음      | 가계부 모음. 방 하나로 들어간다.                                       |
| 묶음 소속 | 가계부와 묶음의 다대다 연결.                                           |

확정

- 가계부를 만들 때 이름과 별도로 **param(필드 구성)** 을 정한다. 결제방식·카테고리 같은 태그는 **가계부마다** 관리한다.
- 한 가계부는 **여러 묶음에 동시에** 속할 수 있다. 예: 일본여행 → 여행, 2026. 묶음 집계는 내역 ID로 중복을 제거해 같은 내역을 한 번만 더한다.

기본값

- 고정 필드는 날짜·구분·내용·금액이다. 표·캘린더·합계가 이 필드로 동작한다. 내용은 Notion의 제목 속성에 해당한다.
- 사용자 필드 형태는 텍스트·단일 선택·다중 선택 세 가지다. Notion 샘플의 결제방식·카테고리·누가·비고를 모두 담는다.
- 구분 옵션도 가계부별로 두고, 각 옵션은 수입 또는 지출 성격을 가진다. 예: 11월은 수입·고정지출·지출, 여행은 지출만. 남은 금액은 수입 − 지출 성격 합계다.
- 묶음은 내역을 직접 갖지 않는다. 묶음 방에서 내역을 추가하면 날짜에 맞는 가계부를 제안하고 사용자가 확인한다.
- 묶음 안에 묶음을 두지 않는다(가계부 → 묶음 2단계).
- 묶음 통계는 필드 이름과 옵션 이름이 같으면 합치고, 다르면 따로 보여준다.
- 다중 선택 "누가"는 사람별 포함 금액으로 보여주고 사람별 금액을 더한 합계는 내지 않는다. 비어 있으면 공동이다.
- 태그 이름 변경은 기존 내역에 반영한다. 삭제 대신 보관하며 과거 값은 남긴다. 사용 중인 필드는 숨기기만 하고 형태 변경·삭제는 막는다.

## 4. 가계부 만들기 (기본값)

- 빈 가계부 또는 **기존 가계부 복사**로 시작한다.
- 복사하면 필드 정의와 태그 옵션을 이어받고 기간을 한 달 뒤로 제안한다. 지난 기간의 고정지출 내역을 함께 가져올지 고른다.
- 만들 때 넣을 묶음을 여러 개 고를 수 있다.

## 5. 모바일 화면 (기본값)

흐름: **방 목록 → 방(가계부·묶음) → 표·캘린더·통계 → 내역 입력·설정**. 깊이가 2단계뿐이라 하단 탭 바는 두지 않는다.

| 화면          | 구성                                                                                                                                       |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| 방 목록       | 검색, 전체·가계부·묶음 전환. 줄마다 아이콘·이름·기간·마지막 내역·새 내역 수. 최근 활동 순. 하단 새로 만들기                                |
| 가계부 만들기 | 전체 화면. 시작 방식(빈/복사) → 이름·기간·아이콘 → 필드 → 소속 묶음                                                                        |
| 가계부 방     | 상단 고정: 이름·기간·메뉴, 수입·지출·남은 금액, 표·캘린더·통계 전환. 하단 고정: 내역 추가                                                  |
| 표            | 날짜별 목록(날짜마다 일 합계, 줄마다 내용·금액과 태그). 필터·검색·정렬. 넓게 보기로 가로 스크롤 표                                         |
| 캘린더        | 기간에 맞춘 주 단위 달력, 기간 밖 날은 흐리게. 칸에 일 지출 합계와 수입 표시. 날짜를 누르면 그날 내역과 이 날짜로 추가                     |
| 통계          | 기준 필드 선택(가계부의 선택형 필드 자동), 수입·지출·전체 선택, 가로 막대로 금액·비율. 항목을 누르면 해당 내역                             |
| 내역 입력     | 전체 화면. 구분 → 금액 → 내용(자동완성) → 날짜 → 가계부별 필드(칩, 옵션 즉석 추가) → 비고. 저장·저장하고 계속, 수정 시 삭제                |
| 묶음 방       | 가계부 방과 같은 구조에 가계부별 보기 추가. 표에 소속 가계부 표시, 캘린더는 월 단위 이동, 통계에 가계부별 비교. 추가 시 저장할 가계부 선택 |
| 설정          | 가계부: 이름·기간·아이콘, 필드, 태그 옵션, 소속 묶음, 보관. 묶음: 이름, 포함 가계부, 보관                                                  |
| 로그인        | 두 사람의 Google 계정만 허용                                                                                                               |

## 6. 진행 순서

1. **Storybook**: [UI 컴포넌트 체계](./ui-component-system.md)의 계위대로 원자부터 View까지 조립한다. 이 단계에는 API·저장이 없다.
2. **앱 연결**: DB·API·로그인을 붙인다. 기능 우선순위는 가계부 만들기 → 내역 추가·수정·삭제 → 표·캘린더와 구분 합계 → 통계 → 묶음 → 방 목록(최근 순, 새 내역 수) → 복사해서 만들기와 고정지출 가져오기.

## 7. 미정

- 운영 중인 이전 앱의 데이터(엑셀 이관 650건) 이전. 기본값: 새로 시작하고 나중에 가져오기. 필드 구조가 달라 대응이 필요하다.
- 기술 구성. 기본값: Cloudflare Worker + D1 + Google 로그인 재사용.
- 결제일·이체일 정리 기능의 형태. 결제방식 옵션에 날짜를 붙이는 방식부터 검토한다.
- 내용을 내용·사용처 두 칸으로 나눌지. 기본값: 한 칸.
