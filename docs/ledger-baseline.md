# 가계부 재설계 기준

기준일: 2026-11-03. 재설계의 제품·데이터·화면 기준이다. 컴포넌트 계위와 Storybook 규칙은 [UI 컴포넌트 체계](./ui-component-system.md), 시각 기준은 [우가 디자인시스템](./uga-design-system.md)을 따른다. 이전 앱은 Git 기록 `d3509d5`에 있다.

- **확정**: 사용자가 결정한 사항
- **기본값**: 별도 결정 전까지 따르는 추천안. 바꾸면 이 문서를 먼저 고친다.

## 1. 목표

관리가 복잡했던 이전 앱을 초기화하고 **가계부 본연의 기능을 먼저 완성**한다. (확정)

1. **내역 추가**: 버튼 하나로 가계부에 정의된 필드를 입력하거나 태그를 고른다. Notion 데이터베이스 속성과 같은 방식이다.
2. **적재와 보기**: 가계부 기간 단위로 표·캘린더에 쌓아 보기 쉽게 보여준다.
3. **통계**: 태그(선택형 필드) 단위로 집계한다.

이전 설계에서 유지한다. (확정)

- **상위 가계부**: 여러 가계부를 모아 상위 보기·통계를 만든다. 예: 11월·12월·1월 → 2026, 일본여행 → 여행. (처음에는 "묶음"으로 불렀다)
- **방**: 메신저처럼 가계부 목록에서 골라 들어간다.

둘만 쓰는 가계부가 아니라 **누구나 가입해 혼자 쓰거나 친구와 공유하는 범용 가계부**다. 시작은 웹이다. (확정)

이번 범위에서 제외한다: 자산·저축 반영, 카드 청구, 계획·예산, 엑셀 이관, 가구 단위 관리자/일반 권한, 실시간 동시 편집, 카카오·네이버 로그인(보류), 스토어 앱.

## 2. 참고 샘플: Notion "2026 가계부"

- 한 달은 월급날부터 다음 월급날 전날까지다(예: 10/23~11/22). 수입은 월급날, 지출은 다음 날부터 적는다.
- 열: 날짜, 수입·고정지출·지출(각각 이름과 금액), 결제방식(카드·자동이체), 카테고리(단일 선택), 누가(다중 선택, 비어 있으면 공동), 비고.
- 이름은 `무엇_어디서` 형식이다. 예: `장보기_쿠팡`.
- 고정지출은 결제수단이 아니라 매달 나가는 돈인지로 구분한다. 관리비는 카드로 내도 고정지출이다.
- 바람: 신용카드 결제일·자동이체일을 정리해 접어 두고, 자동이체 날짜를 정리해 매번 여러 날을 확인하지 않는다.

## 3. 데이터 모델

타입과 검증·합계 함수는 [src/shared/ledger.ts](../src/shared/ledger.ts), 합성 데이터는 [src/stories/fixtures.ts](../src/stories/fixtures.ts)에 있고 Storybook `00 Guide/데이터 모델`에서 확인한다.

| 개념        | 내용                                                                                                            |
| ----------- | --------------------------------------------------------------------------------------------------------------- |
| 가계부      | 방 하나. 이름, 기간, 아이콘, 하위 가계부 목록을 가진다. 하위가 없으면 필드 정의·태그 옵션을 갖고 내역을 담는다. |
| 상위 가계부 | 하위 가계부가 있는 가계부. 필드·내역 없이 아래 모든 가계부의 내역을 모아 보여준다.                              |
| 필드 정의   | 내역을 담는 가계부의 param. 고정 필드와 사용자 필드로 나뉜다.                                                   |
| 태그 옵션   | 선택형 필드의 옵션. 가계부별로 이름·색·순서·보관 상태를 가진다.                                                 |
| 내역        | 정확히 한 가계부(하위가 없는 가계부)에 속한다. 고정 필드 값과 사용자 필드 값을 가진다.                          |

확정

- 가계부를 만들 때 이름과 별도로 **param(필드 구성)** 을 정한다. 결제방식·카테고리 같은 태그는 **가계부마다** 관리한다.
- 한 가계부는 **여러 상위 가계부에 동시에** 속할 수 있다. 예: 일본여행 → 여행, 2026. 상위 집계는 같은 내역을 한 번만 더한다.
- 가계부 방과 묶음 방을 따로 두지 않는다. **가계부 방 하나**가 하위 유무에 따라 보여주는 것을 바꾼다.
- **상위 가계부는 자기 내역을 갖지 않는다.** 내역은 항상 하위가 없는 가계부에만 쌓이고, 상위는 모아 보기만 한다.
- **여러 단계로 쌓을 수 있다**(예: 2026 › 하반기 › 11월). 자기 자신이나 자기 아래 가계부 밑으로는 넣을 수 없다(순환 금지). 상위의 합계는 아래 모든 가계부의 내역이다.

기본값

- 고정 필드는 날짜·구분·내용·금액이다. 표·캘린더·합계가 이 필드로 동작한다. 내용은 Notion의 제목 속성에 해당한다.
- 사용자 필드 형태는 텍스트·단일 선택·다중 선택 세 가지다. Notion 샘플의 결제방식·카테고리·누가·비고를 모두 담는다.
- 구분 옵션도 가계부별로 두고, 각 옵션은 수입 또는 지출 성격을 가진다. 예: 11월은 수입·고정지출·지출, 여행은 지출만. 남은 금액은 수입 − 지출 성격 합계다.
- 상위 가계부 방에서 내역을 추가하면 아래 가계부 중 날짜에 맞는 것을 제안하고 사용자가 확인한다.
- 상위 가계부의 기간은 아래 가계부 기간을 모두 덮도록 정한다.
- 상위 통계는 필드 이름과 옵션 이름이 같으면 합치고, 다르면 따로 보여준다.
- 다중 선택 "누가"는 사람별 포함 금액으로 보여주고 사람별 금액을 더한 합계는 내지 않는다. 비어 있으면 공동이다.
- 태그 이름 변경은 기존 내역에 반영한다. 삭제 대신 보관하며 과거 값은 남긴다. 사용 중인 필드는 숨기기만 하고 형태 변경·삭제는 막는다.

## 4. 가계부 만들기 (기본값)

- 종류를 고른다: **내역을 적는 가계부** 또는 **상위 가계부**.
- 내역을 적는 가계부는 빈 가계부 또는 **기존 가계부 복사**로 시작한다. 복사하면 필드 정의와 태그 옵션을 이어받고 기간을 한 달 뒤로 제안한다. 지난 기간의 고정지출 내역을 함께 가져올지 고른다.
- 상위 가계부는 하위 가계부만 고른다.
- 둘 다 만들 때 속할 상위 가계부를 여러 개 고를 수 있다. 순환이 생기는 선택지는 보이지 않는다.

## 5. 모바일 화면 (기본값)

흐름: **방 목록 → 가계부 방 → 표·캘린더·통계(·하위) → 내역 입력·설정**. 앱 전체 하단 탭 바는 두지 않고, 방 안에서만 보기 전환과 내역 추가를 하단에 둔다.

| 화면          | 구성                                                                                                                                                                                                                                                     |
| ------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 방 목록       | 검색. 모든 가계부가 줄마다 아이콘·이름·기간(상위는 하위 수)·마지막 내역(하위 포함)·새 내역 수. 최근 활동 순. 하단 새 가계부                                                                                                                              |
| 가계부 만들기 | 전체 화면. 종류(내역을 적는 가계부/상위 가계부) → 시작 방식(빈/복사) → 이름·기간·아이콘 → 필드(상위는 하위 가계부) → 상위 가계부                                                                                                                         |
| 가계부 방     | 상단 고정: 이름·기간·메뉴, 수입·지출·남은 금액. 하단 고정: 표·캘린더·통계 전환과 둥근 내역 추가 버튼(엄지 영역). 상위 가계부는 아래 모든 내역에 원본 가계부를 표시하고, 캘린더는 월 단위 이동, 하단에 하위 보기를 더하며, 추가 시 저장할 가계부를 고른다 |
| 표            | 날짜별 목록(날짜마다 일 합계, 줄마다 내용·금액과 태그). 필터·검색·정렬. 넓게 보기로 가로 스크롤 표                                                                                                                                                       |
| 캘린더        | 기간에 맞춘 주 단위 달력, 기간 밖 날은 흐리게. 칸에 일 지출 합계와 수입 표시. 날짜를 누르면 그날 내역과 이 날짜로 추가                                                                                                                                   |
| 통계          | 기준 필드 선택(가계부의 선택형 필드 자동, 기본은 옵션이 가장 많은 단일 선택 필드, 상위 가계부는 가계부별 비교 포함), 수입·지출·전체 선택, 가로 막대로 금액·비율. 항목을 누르면 해당 내역                                                                 |
| 내역 입력     | 전체 화면. 구분 → 금액 → 내용(자동완성) → 날짜 → 가계부별 필드(칩, 옵션 즉석 추가) → 비고. 저장·저장하고 계속, 수정 시 삭제                                                                                                                              |
| 설정          | 내역을 적는 가계부: 이름·기간·아이콘, 필드, 태그 옵션, 상위 가계부, 보관. 상위 가계부: 이름·아이콘, 하위 가계부, 상위 가계부, 보관                                                                                                                       |
| 로그인·가입   | Google 로그인. 처음 로그인하면 아이디·표시 이름·프로필 그림을 정하고 약관에 동의한다                                                                                                                                                                     |

## 6. 진행 순서

1. **Storybook**: [UI 컴포넌트 체계](./ui-component-system.md)의 계위대로 원자부터 View까지 조립한다. 이 단계에는 API·저장이 없다.
2. **앱 연결**: DB·API·로그인을 붙인다. 기능 우선순위는 가계부 만들기 → 내역 추가·수정·삭제 → 표·캘린더와 구분 합계 → 통계 → 상위 가계부 → 방 목록(최근 순, 새 내역 수) → 복사해서 만들기와 고정지출 가져오기.

## 7. 계정·친구·공유

확정

- 로그인은 **Google만** 쓴다. 카카오·네이버는 보류한다. 처음 로그인하면 계정을 만들고 **아이디와 프로필**을 정한다.
- 기본 흐름은 **친구 추가(아이디) → 방에 친구 초대 → 상대 수락**이다.
- **초대 링크는 서비스 가입용**이다. 방에 들어가는 권한은 주지 않는다.
- 공유한 가계부를 **사람마다 자기 상위 가계부 아래에 둔다.** 예: 나는 일본여행을 내 2026 아래에, 친구는 자기 여행 아래에 둔다. 상위 가계부는 각자의 집계용이다.

기본값

- 계정: 사용자(아이디·표시 이름·아바타)와 로그인 정보(제공자·고유번호·이메일)를 분리해, 나중에 다른 로그인을 붙여도 계정이 하나로 남게 한다.
- 아이디: 영문 소문자·숫자·밑줄 4–20자, 중복·예약어 금지. 30일에 한 번 바꿀 수 있고, 바꾼 이전 아이디는 30일간 아무도 쓸 수 없다. 공개되는 프로필은 아이디·표시 이름·아바타뿐이다.
- 친구: 아이디가 정확히 일치할 때만 찾는다. 요청 → 수락으로 맺고, 삭제·차단할 수 있다. 친구라는 사실만으로는 어떤 데이터도 볼 수 없다.
- 공유 단위는 **내역을 적는 가계부**다. 소유자 1명과 멤버(편집·보기)가 있다.

| 동작                                                    | 소유자 | 편집 | 보기 |
| ------------------------------------------------------- | ------ | ---- | ---- |
| 내역 읽기                                               | ✓      | ✓    | ✓    |
| 내역 추가·수정·삭제, 태그 옵션 추가                     | ✓      | ✓    | ✗    |
| 기간·필드 구성, 멤버 초대·권한 변경·내보내기, 보관·삭제 | ✓      | ✗    | ✗    |

- 상위 가계부는 만든 사람만 보는 개인 폴더다. 자기가 볼 수 있는 가계부(공유받은 것 포함)를 넣는다. 상위 자체는 공유하지 않는다.
- 상위의 **하위 전부 공유**는 그 아래 가계부 중 **내가 소유한 것**에 친구를 한 번에 초대한다. 받은 사람은 수락할 때 자기 쪽에 같은 이름의 상위를 만들어 묶을 수 있다. 공유 중인 상위에 하위를 더하면 같이 보는 사람에게도 공유할지 묻는다.
- 초대 링크로 **새로 가입한 계정**은 초대한 사람과 자동으로 친구가 되고, 초대한 사람에게 알린다. 이미 가입한 사람이 링크를 열면 일반 친구 요청이 된다.
- 소유자가 탈퇴하면 공유 중인 가계부는 편집 멤버가 수락해야 소유권이 넘어간다. 넘길 사람이 없으면 삭제를 안내한다. 탈퇴한 사람이 남의 가계부에 적은 내역은 남기고 작성자를 "탈퇴한 사용자"로 표시한다.
- 화면: 최상위 하단 탭은 가계부·친구·내 정보다. 방에 들어가면 방 하단 막대로 바뀐다. 공유된 방에는 멤버 아바타를 보인다.
- 동시 편집: 내역과 가계부에 `version`을 두고, 바꾼 필드만 보낸다. 다른 필드는 자동으로 합치고, 같은 필드를 동시에 고쳤으면 저장을 멈추고 두 값을 보여 고르게 한다. 요청 ID로 재시도해도 한 번만 저장한다. `createdAt`·`updatedAt`은 서버가 정한다.
- 새 내역 수는 사람별·방별 마지막으로 읽은 시각으로 센다.

## 8. 보안 기준 (기본값, 서버 구현 전 필수)

권한

1. 상위 가계부의 `childIds`는 **가리키기일 뿐 권한이 아니다.** 상위 집계와 내역 조회는 요청 시점에 요청자가 멤버인 가계부만 포함한다. 상위에 넣을 때도 요청자가 볼 수 있는 가계부인지 검사하고, 상위의 구성은 그 소유자에게만 보인다.
2. 가계부·내역·태그를 다루는 모든 요청은 서버가 **현재 멤버십과 권한**을 매번 확인한다(위 권한표). 내역을 다른 가계부로 옮기면 양쪽을 확인한다. 편집 중에 권한이 낮아지면 저장 시 거절한다.
3. 방 초대는 특정 사용자에게만 보내고, 수락 전에는 아무 권한도 없다. 하위 전부 공유는 서버에서 소유자가 아닌 가계부를 뺀다.
4. 멤버 내보내기와 탈퇴는 즉시 효력이 있다. 이후 요청과 실시간 연결을 끊는다. 삭제된 가계부는 다른 사람의 상위에서 1번 규칙으로 빠진다.

초대 링크와 계정

5. 초대 토큰은 128비트 무작위 값이고 서버에는 해시만 둔다. 다시 발급하면 이전 링크는 무효이며 만료(30일)와 가입 상한(20명)을 둔다. 링크를 연 뒤 주소에서 토큰을 지우고, 로그·분석에 남기지 않으며 `Referrer-Policy`를 명시한다.
6. Google 계정은 고유번호(`sub`)로 식별하고 이메일로 계정을 찾거나 합치지 않는다. 로그인 과정에서 `state`·`nonce`·PKCE를 검증한다.
7. 세션 쿠키는 `HttpOnly; Secure; SameSite=Lax`이고 로그인할 때 새로 발급한다. 로그아웃하면 서버 세션도 지운다. 데이터를 바꾸는 요청은 `Origin`을 확인한다.
8. 가입·아이디 검색·친구 요청·초대 링크 발급에 횟수 제한을 둔다. 차단한 사람에게는 검색 결과와 요청이 보이지 않는다. 이메일은 다른 사용자에게 보내지 않는다.

공유 데이터 표시

9. 다른 사람이 저장한 값은 서버와 화면 양쪽에서 검증한다. 색은 `#RRGGBB`만, 아이콘·아바타는 정해진 이름만 받는다. 화면에서는 `isHexColor`와 Uga 이름 목록으로 이미 막는다(Storybook `UnsafeColor`·`UnknownIcon`).
10. 이름·아이디·태그·메모는 React가 글자로 그리게 두고 HTML로 넣지 않는다.

운영

11. 보안 헤더: CSP(`script-src 'self'`), `frame-ancestors 'none'`, HSTS, `X-Content-Type-Options`. 외부 글꼴·스크립트는 직접 제공하거나 CSP에 필요한 것만 연다.
12. 멤버·권한 변경, 삭제, 소유권 이전을 기록한다. 기기에 내역을 저장하게 되면 로그아웃할 때 지운다.

서버를 만든 뒤 가짜 계정 두 개로 로컬에서 확인한다: ID만 바꾼 접근이 모두 거절되는지, 멤버에서 빠진 직후 상위 집계와 조회에서 그 가계부가 사라지는지, 하위 전부 공유가 제3자 가계부를 포함하지 않는지, 잘못된 색·아이콘 값을 서버가 거절하는지.
