# 가계부 계위와 사용자 역할

2026-09-17 사용자 결정 및 구현 계약. 운영 반영과 검증 결과는 [구현 현황](./implementation-status.md)에 기록한다.

## 구조와 집계

가계부는 여러 최상위와 임의 깊이의 하위를 가진다. 예를 들어 `2026 / 1월 / 여행`, `2026 / 2월`, `2027`을 구성할 수 있다. 기존 메인 가계부도 다른 가계부 아래로 이동할 수 있다.

- 가계부마다 부모는 최대 하나다. 자신·자손 아래 이동 및 다른 가구로 이동은 거절한다.
- 이동 시 모든 하위가 함께 이동한다. 같은 단계의 순서는 저장하며 트리 접기·펼치기와 경로를 제공한다.
- 끌어 놓기로 이동 대상을 정하거나 위치 변경 창과 위·아래 버튼을 사용한다. 모바일·키보드에서는 동일한 위치 선택 기능을 사용한다.
- 각 가계부는 직접 기록만 또는 하위 전체를 조회한다. 가상 ‘전체 보기’는 모든 원본 거래를 정확히 한 번 포함하며 저장 대상이 될 수 없다.
- 월, 연도, 가계부 설정 기간으로 조회한다. 거래의 실제 날짜를 유지하며 활동 기간 밖의 거래도 기록할 수 있다.
- 상위에서 보이는 하위 거래는 원본 가계부로 이동해 편집한다.
- 가계부 예산은 독립적이다. 하위 예산을 상위 예산에 자동으로 더하지 않는다. 연도/전체 보기에서 개별 가계부의 기간 예산을 연간·통합 예산으로 간주하지 않는다.
- 자산·카드·저축은 가구 공유 범위다. 계위 이동은 거래 소유·자산 효과·카드 이용 사실을 변경하지 않는다.
- 분류 대응은 자식→부모 관계마다 차례로 적용한다. 부모를 바꾸면 이동한 노드의 기존 분류 대응을 비우고 새 부모 기준으로 다시 설정한다. 원본 태그는 보존한다.

## 역할

초기 본인(`u1`)은 `admin`, 배우자(`u2`)는 `user`다. 이메일 등 로그인 비밀 설정은 문서·저장소에 기록하지 않는다.

| 동작 | admin | user |
| --- | --- | --- |
| 가계부·자산·카드 조회, 원본 내역 편집 | 가능 | 가능 |
| 기존 가계부 일반 설정·예산·태그·계획 편집 | 가능 | 가능 |
| 가계부 생성·이동·순서 변경·보관/해제 | 가능 | 불가 |
| 구성원 역할 변경 | 가능 | 불가 |
| JSON 백업·CSV 내보내기·기존 가계부 CSV 거래 가져오기 | 가능 | 가능 |
| 구조를 교체하는 전체 백업 복원·엑셀 가져오기 | 가능 | 불가 |

역할과 지출 귀속은 별개다. 역할 변경은 기존 로그인에도 즉시 적용되며 마지막 관리자를 일반 사용자로 바꾸는 요청은 거절한다. 새로운 구성원 초대나 가계부별 비공개 권한은 추가하지 않는다.

## 여러 관리자의 동시 변경

가구에 `hierarchyVersion`을 둔다. 관리자가 구조 버전 10에서 각각 이동을 시작하면 첫 요청이 저장되어 11이 된다. 두 번째 요청은 HTTP 409 `HIERARCHY_CONFLICT`로 거절한다. 서로 다른 가계부를 이동해도 같은 구조 버전 검사를 거친다. 예를 들어 A를 B 아래로, B를 A 아래로 동시에 옮겨 순환이 생기는 일을 막는다.

1. 화면이 이동/생성/권한 편집을 시작할 때 버전을 고정한다.
2. 서버가 소속·현재 역할·대상·순환·버전을 검사한다.
3. 같은 D1 원자적 배치 안에서 현재 admin과 계위 버전을 다시 검사하고 변경·순서·계위 버전 증가·감사 이력·가구 revision·요청 결과를 저장한다.
4. 충돌한 화면은 최신 트리와 기존 이동 의도를 보여준다. 사용자가 새 목적지를 확인하고 명시적으로 다시 적용한다. 자동 덮어쓰기/자동 충돌 재시도는 하지 않는다.
5. 응답 유실 재시도는 같은 mutation ID로 저장 결과를 확인한다. 이미 반영한 이동을 다시 적용하지 않는다.

역할 변경도 같은 계위 버전을 증가시킨다. 편집 도중 admin이 해제되면 서버가 403으로 거절하며 화면 권한을 갱신한다. 전체 백업 복원은 더 넓은 가구 `revision` 검사와 같은 배치의 admin 검사를 사용하고 계위 버전도 증가시킨다.

## 데이터와 호환성

- `0012_hierarchy_roles.sql`: `users.role`, `households.hierarchy_version`, `ledgers.sort_order` 추가. 기존 거래와 자산 금액은 변경하지 않는다.
- 기존 `kind` 값은 호환을 위해 남긴다. 집계나 권한에는 사용하지 않는다. 기존 main을 다른 부모 아래로 옮기면 legacy 제약을 충족하도록 purpose로 저장한다.
- 구조 요청에는 `expectedHierarchyVersion`이 필요하다. 이동/일반 수정에는 기존 `expectedVersion`도 유지한다.
- 백업 schema 2는 부모와 순서를 저장한다. schema 1 복원은 누락된 순서를 보정한다. 복원 시 순환·참조·순서를 검사하며 로그인·사용자 역할은 백업에서 복원하지 않는다.
