# 우리의 가계부

부부가 함께 쓰는 로컬 웹 가계부입니다. 메인·목적별 가계부의 수입·지출, 사용자 정의 태그, 명시적 자산 반영, 자산 이동·잔액 조정·저축 통계와 공동 사용 흐름을 개발하고 있습니다. 전체 기능이나 운영 배포가 완료된 상태는 아닙니다.

원장·태그·자산·대출·카드·통장·계획·통계·엑셀 이관·백업과 공동 편집을 구현하고 검증합니다. 최신 통과 결과는 [구현 현황](./docs/implementation-status.md), 원본 자료 대조와 미확정 항목은 [Excel 검증 보고서](./docs/excel-parity-audit.md)에 기록합니다.

## 로컬 실행

Node.js 24와 npm을 준비한 뒤 프로젝트 폴더에서 실행합니다.

```sh
node --version
npm ci
npm run dev
```

[http://localhost:5173](http://localhost:5173)을 엽니다. 연결되지 않으면 [http://127.0.0.1:5173](http://127.0.0.1:5173)을 사용합니다.

`npm run dev`는 다음을 순서대로 처리합니다.

1. `.dev.vars`가 없으면 `.dev.vars.example`을 복사합니다.
2. 로컬 D1에 마이그레이션과 가상 예시 데이터를 적용합니다.
3. 웹 앱을 빌드합니다.
4. Vite 웹 서버 `5173`과 로컬 Worker `8787`을 함께 실행합니다. 웹 화면의 `/api` 요청과 WebSocket은 Worker로 전달됩니다.

종료는 터미널에서 `Ctrl+C`를 누릅니다. 로컬 데이터는 `.wrangler/state`에 유지됩니다. `dev`를 다시 실행해도 `INSERT OR IGNORE`로 넣은 기존 예시 데이터와 사용자가 수정한 값은 덮어쓰지 않습니다.

### 두 사용자로 확인하기

- 일반 브라우저 창에서 **나**, 시크릿 창이나 별도 브라우저 프로필에서 **와이프**로 시작합니다. 같은 브라우저 세션의 탭은 로그인 쿠키를 공유하므로 두 사용자 확인에는 분리된 세션이 필요합니다.
- 같은 가계부에서 접속·편집 위치와 저장 결과를 확인합니다. 새 내역은 기본적으로 **저장 버튼**으로 등록하며, 입력 완료 후 자동 저장을 선택할 수도 있습니다. 기존 내역은 필드 이탈 후 유효한 변경을 자동 저장하며, 끄고 수동으로 저장할 수도 있습니다.
- 기기 초안은 가구·계정·가계부별로 보관합니다. 응답을 받지 못한 요청은 같은 요청 번호로 재확인하며 재시도로 중복 생성하지 않습니다. 충돌이나 상대방 삭제 시 자동 저장을 멈춥니다.
- 메인에 표시된 목적 가계부의 거래는 원본 가계부로 이동해 수정합니다.
- 목적 가계부의 예산 설정은 자산을 바꾸지 않습니다. 거래에서 자산별 반영 금액을 지정했을 때만 해당 자산에 반영합니다. 지정한 금액의 합계는 거래 금액과 같아야 합니다.

### 분류와 돈의 흐름

- 가계부에는 **수입·지출만** 입력합니다. 태그 유형과 옵션은 직접 만들고 단일/복수 선택, 사용 가계부, 이름·색상·순서·보관을 관리합니다. 거래 입력 중에도 없는 옵션을 만들 수 있습니다.
- 태그 이름이나 옵션을 선택해도 금액은 변하지 않습니다. 자산에 반영하려면 거래의 자산별 금액을 명시합니다. 태그 조건에 따른 자동 배분은 후속 설정입니다.
- 자산 화면에서 자산을 만들고 **자산 이동·기록일 기준 잔액 맞추기**를 별도 이력으로 기록합니다. 잔액 맞추기도 차액·날짜·사유·작성자를 남기며 가계부 수입·지출을 만들지 않습니다.
- 저축은 자산의 **저축 집계 여부**를 명시해 계산합니다. 유입·인출·순저축을 보며 최초 잔액·잔액 조정·저축 집계 자산끼리 이동은 실적에 넣지 않습니다. 태그나 현재 설정 변경으로 과거 실적을 다시 계산하지 않습니다.

## 데이터와 실행 범위

- [초기 스키마](./migrations/0001_schema.sql)와 [태그·자산 마이그레이션](./migrations/0002_tags_assets.sql)은 DB 구조·기존 앱 데이터를 전환하고, [예시 데이터](./seeds/demo.sql)는 로컬 가상 자료를 넣습니다. 두 역할을 분리했습니다.
- 이전 앱의 분류 문자열은 태그 옵션으로, 저축·이체 거래는 별도 자산 이동으로 옮깁니다. 이전 기록을 보존하면서 현재 가계부에는 수입·지출만 표시합니다. 이 전환은 원본 Excel 가져오기와 다릅니다.
- 실제 원본 Excel은 변경하지 않습니다. 원본 대조 테스트는 별도 임시 DB에서 수행하며 기존 로컬 PoC 데이터와 분리합니다. 실제 자료 반영은 데이터 관리에서 미리보기와 매핑을 확인한 뒤 진행합니다.
- 통장 정보는 결제수단 정보입니다. 자산에 이중 합산하거나 계좌 잔액을 자동 계산하지 않습니다.
- 카드 구매만 소비 지출입니다. 청구 예상액·납부일은 별도 정보이며 지출을 다시 생성하지 않습니다. 할부·취소·이월·은행 휴일 보정은 아직 지원하지 않습니다.
- 가구당 Durable Object 하나로 접속·편집 위치·변경 순번을 공유하고, 누락된 변경은 API 재조회로 복구하는 구조입니다.

**Google OIDC 코드는 구현했으며 실제 두 계정과 원격 배포는 아직 연결하지 않았습니다.** [운영 로그인 설정](./docs/auth-deployment.md)에 필요한 값과 절차를 정리했습니다. 데모 인증은 `DEMO_MODE=true`와 로컬 호스트 조건을 모두 요구하며 운영에서는 허용하지 않습니다. Cloudflare 실제 사용량·무료 운영 비용·원격 성능은 별도 검증이 필요합니다.

## Excel 가져오기와 백업

- 데이터 관리 → 원본 XLSX 선택 → 결제수단 연결 → 미리보기 → 반영 순서로 사용합니다.
- 같은 원본은 같은 식별자로 다시 가져옵니다. 원본 위치로 중복을 판별하며 변경된 원문은 조용히 덮어쓰지 않습니다.
- 날짜 없는 기록, 저축 자산 연결, 예비금의 중복 여부는 검토함에 보존합니다. 검토 완료 상태를 바꾸는 것만으로 금액이 반영되지는 않습니다.
- 최초 관측일 이전의 자산 잔액은 미확인입니다. 월말 관측 잔액과 이후 조정은 저축 실적을 만들지 않습니다.
- JSON은 전체 복원용이며 현재 가구 자료를 교체합니다. CSV는 거래 교환용입니다. 세션과 로그인 비밀값은 백업하지 않습니다.

## 개발 명령

| 명령 | 역할 |
| --- | --- |
| `npm run dev` | 로컬 DB 준비·빌드 후 웹과 Worker 함께 실행 |
| `npm run db:init` | 로컬 마이그레이션과 가상 예시 데이터 적용 |
| `npm run typecheck` | TypeScript 검사 |
| `npm test` | Vitest 테스트 실행 |
| `npm run build` | 웹 앱 빌드 |
| `npm run check` | 타입 검사·테스트·빌드 순서로 실행 |
| `npm run test:e2e` | Playwright 브라우저 테스트 실행 |
| `npm run format` | 선택적으로 소스·테스트·설정 파일의 서식 정리 |

명령의 존재가 검증 완료를 뜻하지는 않습니다. 실제 실행 결과와 남은 범위는 [구현 현황](./docs/implementation-status.md)에 기록합니다.

### 브라우저 테스트 준비

프로젝트에 고정된 Playwright 버전으로 Chromium을 설치한 뒤 실행합니다.

```sh
npx playwright install chromium
npm run test:e2e
```

[E2E 실행 스크립트](./scripts/e2e.mjs)는 매번 별도의 임시 DB를 만들며 개발 DB를 변경하지 않습니다. 웹 앱을 빌드한 뒤 Worker가 정적 파일과 API를 함께 제공하는 `8790` 포트에서 검사합니다. 개발 화면 `5173`의 Vite 프록시와 다른 경로지만, 실제 원격 배포 검증은 아닙니다.

### 설치 중 인증서 오류가 날 때

Node.js 24인지 확인한 뒤 시스템 인증서를 사용해 설치합니다.

```sh
NODE_USE_SYSTEM_CA=1 npm ci
```

인증서 검증을 끄는 `strict-ssl=false`나 `NODE_TLS_REJECT_UNAUTHORIZED=0`은 사용하지 않습니다.
