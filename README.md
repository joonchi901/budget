# 우리의 가계부

부부가 함께 쓰는 웹 가계부입니다. 메인·목적별 가계부의 수입·지출, 사용자 정의 태그, 명시적 자산 반영, 자산 이동·잔액 조정·저축 통계와 공동 사용 흐름을 개발하고 있습니다. Cloudflare 호스팅과 Google 로그인 연결을 완료했고 본인 계정의 실제 로그인·실시간 연결을 확인했습니다. 배우자 로그인과 실제 2인 공동 동작은 확인 대기 중입니다.

원장·태그·자산·대출·카드·통장·계획·통계·엑셀 이관·백업과 공동 편집을 구현하고 검증합니다. 최신 통과 결과는 [구현 현황](./docs/implementation-status.md), 원본 자료 대조와 미확정 항목은 [Excel 검증 보고서](./docs/excel-parity-audit.md)에 기록합니다.

## 가계부 열고 사용하기

1. 첫 화면에서 가계부를 방처럼 골라 들어갑니다. 최상위 가계부가 최근 기록 수정 순으로 보이고, 이름 검색으로 하위 가계부까지 찾을 수 있습니다. 관리자는 **새 가계부**로 방을 만듭니다.
2. 방 안의 고정 헤더에서 현재 가계부 이름·상위 경로·보기를 확인합니다. **목록 / 캘린더 / 통계 / 계획·일정**은 같은 가계부 안에서 전환됩니다. **하위 가계부**를 펼치면 월별·목적별 방에 들어가거나 관리자가 하위 방을 만들 수 있습니다.
3. **가계부 목록**으로 돌아가 다른 방을 고릅니다. **전체 가계부**는 모든 원본 기록을 중복 없이 모아 보는 화면입니다. 자산·카드/통장·태그 설정·데이터 관리는 **우리 집 공통** 메뉴에 있습니다.

- 모바일에서는 방 이름과 보기 버튼이 위에 유지되고, 아래에서 **내역 추가**와 **더보기**에 접근합니다. 캘린더 날짜를 누르면 그 날짜의 내역을 추가할 수 있습니다.
- URL에 가계부·보기·조회 월을 담아 새로고침과 브라우저 뒤로/앞으로 이동 시 복원합니다. 목록/캘린더 기본 선택은 현재 브라우저에서 **계정·가계부별**로 기억합니다. 세부 검색·분석 조건은 각 화면에서 설정합니다.
- 거래와 통계는 현재 방과 선택한 하위 범위에, 계획은 해당 원본 가계부에 속합니다. 자산과 순저축은 가구 공동 기준이며 통계 화면에도 범위를 표시합니다.
- 기존 공동 열람·기록 편집 권한을 유지합니다. 가계부 생성·계위/순서 변경·보관·구성원 역할 관리는 관리자만 할 수 있습니다. 동시 계위 변경의 버전 검사와 충돌 안내도 유지합니다.

## 로컬 실행

Node.js 24와 npm을 준비한 뒤 프로젝트 폴더에서 실행합니다.

```sh
node --version
npm ci
npm run dev
```

[http://localhost:5173](http://localhost:5173)을 엽니다. 연결되지 않으면 [http://127.0.0.1:5173](http://127.0.0.1:5173)을 사용합니다.

`npm run dev`는 다음을 순서대로 처리합니다.

1. `.dev.vars`가 없으면 `.dev.vars.example`을 복사합니다.
2. 로컬 D1에 마이그레이션과 가상 예시 데이터를 적용합니다.
3. 웹 앱을 빌드합니다.
4. Vite 웹 서버 `5173`과 로컬 Worker `8787`을 함께 실행합니다. 웹 화면의 `/api` 요청과 WebSocket은 Worker로 전달됩니다.

종료는 터미널에서 `Ctrl+C`를 누릅니다. 로컬 데이터는 `.wrangler/state`에 유지됩니다. `dev`를 다시 실행해도 `INSERT OR IGNORE`로 넣은 기존 예시 데이터와 사용자가 수정한 값은 덮어쓰지 않습니다.

### 두 사용자로 확인하기

- 일반 브라우저 창에서 **나**, 시크릿 창이나 별도 브라우저 프로필에서 **와이프**로 시작합니다. 같은 브라우저 세션의 탭은 로그인 쿠키를 공유하므로 두 사용자 확인에는 분리된 세션이 필요합니다.
- 같은 가계부에서 접속·편집 위치와 저장 결과를 확인합니다. 새 내역은 기본적으로 **저장 버튼**으로 등록하며, 입력 완료 후 자동 저장을 선택할 수도 있습니다. 기존 내역은 필드 이탈 후 유효한 변경을 자동 저장하며, 끄고 수동으로 저장할 수도 있습니다.
- 기기 초안은 가구·계정·가계부별로 보관합니다. 응답을 받지 못한 요청은 같은 요청 번호로 재확인하며 재시도로 중복 생성하지 않습니다. 충돌이나 상대방 삭제 시 자동 저장을 멈춥니다.
- 메인에 표시된 목적 가계부의 거래는 원본 가계부로 이동해 수정합니다.
- 목적 가계부의 예산 설정은 자산을 바꾸지 않습니다. 거래에서 자산별 반영 금액을 지정했을 때만 해당 자산에 반영합니다. 지정한 금액의 합계는 거래 금액과 같아야 합니다.

### 분류와 돈의 흐름

- 가계부에는 **수입·지출만** 입력합니다. 태그 유형과 옵션은 직접 만들고 단일/복수 선택, 사용 가계부, 이름·색상·순서·보관을 관리합니다. 거래 입력 중에도 없는 옵션을 만들 수 있습니다.
- 태그 이름이나 옵션을 선택해도 금액은 변하지 않습니다. 자산에 반영하려면 거래의 자산별 금액을 명시합니다. 태그 조건에 따른 자동 배분은 후속 설정입니다.
- 자산 화면에서 자산을 만들고 **자산 이동·기록일 기준 잔액 맞추기**를 별도 이력으로 기록합니다. 잔액 맞추기도 차액·날짜·사유·작성자를 남기며 가계부 수입·지출을 만들지 않습니다.
- 저축은 자산의 **저축 집계 여부**를 명시해 계산합니다. 유입·인출·순저축을 보며 최초 잔액·잔액 조정·저축 집계 자산끼리 이동은 실적에 넣지 않습니다. 태그나 현재 설정 변경으로 과거 실적을 다시 계산하지 않습니다.

## 데이터와 실행 범위

- [초기 스키마](./migrations/0001_schema.sql)와 [태그·자산 마이그레이션](./migrations/0002_tags_assets.sql)은 DB 구조·기존 앱 데이터를 전환하고, [예시 데이터](./seeds/demo.sql)는 로컬 가상 자료를 넣습니다. 두 역할을 분리했습니다.
- 이전 앱의 분류 문자열은 태그 옵션으로, 저축·이체 거래는 별도 자산 이동으로 옮깁니다. 이전 기록을 보존하면서 현재 가계부에는 수입·지출만 표시합니다. 이 전환은 원본 Excel 가져오기와 다릅니다.
- 실제 원본 Excel은 변경하지 않습니다. 원본 대조 테스트는 별도 임시 DB에서 수행하며 기존 로컬 PoC 데이터와 분리합니다. 실제 자료 반영은 데이터 관리에서 미리보기와 매핑을 확인한 뒤 진행합니다.
- 통장 정보는 결제수단 정보입니다. 자산에 이중 합산하거나 계좌 잔액을 자동 계산하지 않습니다.
- 카드 구매만 소비 지출입니다. 청구 예상액·납부일은 별도 정보이며 지출을 다시 생성하지 않습니다. 할부·취소·이월·은행 휴일 보정은 아직 지원하지 않습니다.
- 가구당 Durable Object 하나로 접속·편집 위치·변경 순번을 공유하고, 누락된 변경은 API 재조회로 복구하는 구조입니다.

**운영 주소는 [우리의 가계부](https://our-budget-production.our-budget.workers.dev)이며, 등록한 두 Google 계정으로 로그인합니다.** 2026-09-17 현재 활성 Worker version은 `9b45323c-23d1-4704-b0e5-d181f77e336c`입니다. 월별 가계부 이관·결제수단 미지정·엑셀 원본 보관 기능을 포함하며, 실제 자료의 반영 결과는 [엑셀 이력 가져오기](./docs/excel-history-import.md)에 기록합니다. Google 웹 클라이언트·운영 callback·최소 로그인 범위와 Worker secrets 네 개를 설정했습니다. 실제 이메일·비밀값은 Git에 기록하지 않습니다.

인증 설정 완료 상태에서 HTTPS 화면, 운영 모드, 비로그인 API·백업·WebSocket의 `401 UNAUTHENTICATED`, 원격 데모의 `404 NOT_FOUND` 검사를 통과했습니다. 본인 Google 계정의 메인 가계부 접근·실시간 연결·새로고침 유지·로그아웃·재로그인을 확인했습니다. 최초 로그인 검증 당시에는 금융 기록을 만들지 않았습니다. **배우자 계정 로그인과 실제 2인 공동 동작은 아직 확인하지 않았습니다.**

운영 배포는 `wrangler.jsonc`의 `production` 환경을 사용합니다. 운영 D1 생성과 migration `0001`~`0013` 적용을 완료했고 가상 seed는 실행하지 않았습니다. `npm run deploy:preview`로 업로드 없이 패키징을 검사하고 `npm run deploy:production`으로 배포합니다. 후속 스키마 변경은 `npm run db:migrate:production`으로 적용합니다. 자세한 연결 상태와 비로그인 접근 검사는 [운영 로그인 설정](./docs/auth-deployment.md)을 따릅니다.

Gmail이 아닌 주소의 Google 계정도 사용할 수 있습니다. 별칭·전달 주소 대신 각 계정이 실제 반환하는 기본 이메일 두 개를 허용목록에 등록해야 합니다. 데모 인증은 `DEMO_MODE=true`와 로컬 호스트 조건을 모두 요구하며 운영에서는 허용하지 않습니다. Cloudflare 실제 사용량·무료 운영 비용·원격 성능은 별도 검증이 필요합니다.

## Excel 가져오기와 백업

- 데이터 관리 → 원본 XLSX 선택 → 가계부 구성 선택 → 미리보기 → 반영 순서로 사용합니다. 결제수단 연결은 선택이며, 미지정 거래도 원장·캘린더·통계에서 조회합니다.
- 원본의 분류·내역·추가 태그와 예비금 항목을 구성하며, 새 가계부 아래 1~12월로 나누어 가져올 수 있습니다. 반영 후 ‘가져온 가계부 보기’에서 전체 기간의 이력을 확인합니다.
- 같은 원본은 같은 식별자로 다시 가져옵니다. 원본 위치로 중복을 판별하며 변경된 원문은 조용히 덮어쓰지 않습니다.
- 날짜 없는 기록, 저축 자산 연결, 예비금의 중복 여부는 검토함에 보존합니다. 검토 완료 상태를 바꾸는 것만으로 금액이 반영되지는 않습니다.
- 최초 관측일 이전의 자산 잔액은 미확인입니다. 월말 관측 잔액과 이후 조정은 저축 실적을 만들지 않습니다.
- JSON은 전체 복원용이며 현재 가구 자료를 교체합니다. CSV는 거래 교환용입니다. 세션과 로그인 비밀값은 백업하지 않습니다.
- 엑셀 원본 탭은 보관된 전체 파일의 시트·셀 조회와 원본 다운로드를 제공합니다. 파일 복원 시 SHA-256을 검증합니다. 자세한 범위는 [엑셀 이력 가져오기](./docs/excel-history-import.md)를 참고하세요.
- 2026 원본의 운영 이관을 완료했습니다. `2026 → 1~12월` 가계부에서 거래 650건을 조회할 수 있습니다. 미확정 자료는 원본 검토함에 남겼으며 실제 DB 전체 행·원본 해시 대조와 운영 화면 확인을 마쳤습니다.

## UI 컴포넌트 명세

`npm run storybook`으로 [로컬 Storybook](http://127.0.0.1:6006)을 엽니다. 실제 앱의 공통 컴포넌트·반응형 배치·가계부 패턴을 가상 데이터로 확인하고 상태·props·조작 검증을 관리합니다. 전체 화면의 공통화 현황과 작업 규칙은 [UI 컴포넌트 체계](./docs/ui-component-system.md)를 따릅니다. `npm run check:ui`는 정적 빌드와 Chromium 320/390/1440px 검사를 실행합니다.

| ------------------- | -------------------------------------------- |

명령의 존재가 검증 완료를 뜻하지는 않습니다. 실제 실행 결과와 남은 범위는 [구현 현황](./docs/implementation-status.md)에 기록합니다.

### 브라우저 테스트 준비

프로젝트에 고정된 Playwright 버전으로 Chromium을 설치한 뒤 실행합니다.

```sh
npx playwright install chromium
npm run test:e2e
```

[E2E 실행 스크립트](./scripts/e2e.mjs)는 매번 별도의 임시 DB를 만들며 개발 DB를 변경하지 않습니다. 웹 앱을 빌드한 뒤 Worker가 정적 파일과 API를 함께 제공하는 `8790` 포트에서 검사합니다. 개발 화면 `5173`의 Vite 프록시와 다른 경로지만, 실제 원격 배포 검증은 아닙니다.

### 설치 중 인증서 오류가 날 때

Node.js 24인지 확인한 뒤 시스템 인증서를 사용해 설치합니다.

```sh
NODE_USE_SYSTEM_CA=1 npm ci
```

인증서 검증을 끄는 `strict-ssl=false`나 `NODE_TLS_REJECT_UNAUTHORIZED=0`은 사용하지 않습니다.

## Git 작업 기록

[GitHub 저장소](https://github.com/joonchi901/budget)의 `main`에서 작업합니다. 문서, 원장 API, 웹 화면, 검증처럼 검토 가능한 작업 단위로 커밋을 나누고, 해당 변경을 검증한 뒤 push합니다. 커밋 메시지에는 변경한 기능이나 해결한 문제를 적습니다.

2026-09-17 현재 개인 GitHub 인증 만료로 원격 push는 대기 중입니다. 별도 GitHub CLI 프로필로 개인 계정의 device flow 승인을 요청했으며 기존 회사 계정은 사용하지 않았습니다. Cloudflare 배포와 Google 로그인 연결은 완료했으며 GitHub 재인증과는 별개입니다.
